第 12 章 性能、移动端与 2026 的工程化

卡通渲染的瓶颈通常不是“光照公式太复杂”，而是“同一个像素被画了太多遍”。一个角色可能有基础色、阴影、Ramp、高光、边缘光、描边、头发透明、眼睛高光等多个 Pass；在手机的小屏幕上，这些层叠起来很容易变成填充率灾难。

先定位，再优化

优化顺序建议是：先用 Frame Debugger 看 Pass 数、用 Profiler 看 CPU/GPU 时间、用 Xcode/Android GPU Inspector 或 RenderDoc 看 overdraw 和带宽；确认瓶颈后再动刀。常见误区是“觉得高光公式太贵”，结果真正的问题是头发叠了六层透明发片。

移动端最容易踩的坑

  • 头发透明：多层发片叠加，每一层都要读深度/混合。能 AlphaTest 就 AlphaTest；必须透明时减少层数、缩短发片、用深度预 Pass 控制排序。
  • 描边：Outline Pass 会把角色再画一遍。线宽按距离/FOV 调整，远处可以关掉；不要把透明发丝也纳入描边。
  • 后处理 Rim：需要深度纹理和人物 Mask，全屏采样在低端机上很贵。能放进主 Pass 的 Rim 就不要放后处理。
  • 贴图：Ramp/LightMap/SDF 都是小图，但数量多。把同类数据打包进 RGB/A 通道，移动端用 ASTC，注意 sRGB 与线性数据的区别。
  • 变体：每个 Boolean Keyword 都可能翻倍。用位掩码/材质层减少组合，配合 Shader Variant Collection 和剥离。
症状先看什么常见处理
角色一多就掉帧Pass 数、材质数、SRP Batcher共享材质、减少关键字、合批
头发边缘发黑/闪烁透明排序、描边 PassAlphaTest、深度预 Pass、排除描边

2026 的工程化视角

新版 URP 的 Render Graph、Shader Graph、SRP Batcher、GPU Instancing、可变速率着色（VRS）都在改变“怎么把画面画出来”，但卡通渲染的核心没变：色阶、阴影、高光、边缘光、描边、材质分层。工具会换，数据布局和美术目标不会换。

如果今天要从零做一个卡通角色，建议的顺序是：先用最少的层跑通（Base + Shadow + Ramp + Outline），再按角色需求加高光/Rim/SDF；每加一层都问三个问题：它解决什么美术问题？它需要什么数据？它在目标平台上值多少钱？

Unity 视角：先用 Frame Debugger 确认你的 Toon Shader 真的只画了预期的 Pass；再用 Profiler 的 GPU 模块看是填充率还是带宽；最后才考虑改公式。移动端优先做“少一层”“少一张全屏图”“少一个变体”，这些收益通常比把 pow 换成 step 大得多。

本章要点：卡通渲染的性能问题主要是 overdraw、Pass、带宽和变体；先定位再优化；头发/描边/后处理 Rim 是三大户；2026 的工具在变，但“图层 + 数据 + 预算”的方法不变。
