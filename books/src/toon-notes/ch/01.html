第 1 章 先拆层：一张日式卡通画面里到底有什么

这份笔记的原作者是知乎的“光阳果”，2021 年以《罪恶装备 Strive》《碧蓝幻想》《原神》《战双帕弥什》为例，拆了日式卡通渲染的一整套做法。它不是某一个 Shader 的参数表，而是一种“把光拆成美术能改的图层”的思路。

原文：知乎专栏《日式卡通渲染笔记（罪恶装备 碧蓝幻想 原神 战双）》，作者光阳果，2021-08-23。本文按 Unity/URP 的视角重新组织，并重绘全部图解，不复制原文图片。

先把画面拆成六件事：亮部与暗部、裁边高光、裁边边缘光、裁边视角光、描边、材质与贴花。所谓“裁边”，就是不让光照连续过渡，而是用阈值、Ramp 或遮罩把它切成几块，让明暗交界线像手绘一样干净。

在 Unity/URP 里，这六层大致落在三个地方：材质的主 Pass、额外的描边 Pass、以及 Renderer Feature 做的全屏后处理。主 Pass 负责基础色、阴影、高光、边缘光；描边 Pass 负责反向外扩；后处理负责屏幕空间的深度边缘光、色调和抗锯齿。

画面层Unity 里通常放哪常用数据
亮部 / 暗部主 Pass 的漫反射分支Base、Shadow、Ramp、LightMap.r
高光主 Pass 的高光分支或 MatCapSpecMask、LightMap.b、MatCap 贴图
边缘光主 Pass 的 Rim 项N·V、RimMask、顶点色
视角光主 Pass 的 N·L 项或 MatCapLightMap、Ramp、视角空间法线
描边独立 Outline Pass平滑法线、顶点 Alpha、描边颜色
材质 / 贴花LayerMap 分支、独立 MeshLayerMap、Decal、顶点色开关

下面这段伪代码不是完整 Shader，只是把“图层”落成一个片元函数的样子。真正写的时候，每个分支都可能变成一张贴图或一个关键字：

float3 ToonLighting(Surface s, Light l)
{
    float ndl = dot(s.normalWS, l.direction);
    float halfLambert = ndl * 0.5 + 0.5;

    float3 diffuse = lerp(s.shadowColor, s.baseColor,
                          smoothstep(s.shadowThreshold,
                                     s.shadowThreshold + s.shadowSoftness,
                                     halfLambert));

    float3 H = normalize(l.direction + s.viewDirWS);
    float spec = pow(saturate(dot(s.normalWS, H)), s.specPower);
    spec = smoothstep(s.specThreshold, s.specThreshold + s.specSoftness, spec);

    float rim = 1.0 - saturate(dot(s.normalWS, s.viewDirWS));
    rim = smoothstep(s.rimThreshold, s.rimThreshold + s.rimSoftness, rim);

    return diffuse + s.specColor * spec * s.specMask + s.rimColor * rim;
}

Unity 视角：不要直接把内置 Standard 材质套一个 Ramp 就当作卡通渲染。Standard 的漫反射、高光、环境光会一起参与，颜色很难压成干净的块。更稳的做法是写一个自定义 URP Lit：自己决定主光、阴影、高光、边缘光各自怎么算，再把不需要的项关掉。

本章要点：日式卡通渲染是“图层 + 美术控制”，不是单个 Shader。先定风格，再决定保留哪几层；每层都要能回答“它由哪张图、哪个顶点通道、哪个 Pass 驱动”。
