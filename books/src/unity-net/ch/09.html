第 9 章 UI 界面模块

原书把 UI 做成“面板 + 管理器”的结构：BasePanel 定义打开/关闭/刷新，PanelManager 管理层级、缓存、打开/关闭；登录、注册、提示、游戏入口等面板各自处理自己的 UI 和网络事件。

要点：面板栈/层级、显示/隐藏、生命周期、事件订阅/退订、缓存常用面板、异步加载、分辨率/安全区适配。UI 不应该每帧轮询网络状态，而是订阅网络事件。

这一章把“网络消息”接到“可见界面”：登录成功 → 大厅；房间列表更新 → 刷新列表；战斗开始 → 切场景/面板。

关键实现：面板生命周期

BasePanel 负责“显示/隐藏/刷新/订阅/退订”，PanelManager 负责“层级/缓存/打开/关闭”。面板不要在 Update 里轮询网络状态，而是订阅 NetManager 的事件；关闭时退订，避免场景切换后回调旧对象。

public abstract class BasePanel : MonoBehaviour
{
    public virtual void OnShow() { }
    public virtual void OnHide() { }
    public virtual void OnRefresh() { }
}

public class PanelManager : MonoBehaviour
{
    readonly Dictionary<string, BasePanel> cache = new();
    readonly List<BasePanel> stack = new();

    public void Open(string key)
    {
        if (!cache.TryGetValue(key, out var panel))
        {
            panel = Instantiate(Resources.Load<BasePanel>("UI/" + key), transform);
            cache[key] = panel;
        }
        panel.gameObject.SetActive(true);
        panel.OnShow();
        stack.Add(panel);
    }

    public void Close(BasePanel panel)
    {
        panel.OnHide();
        panel.gameObject.SetActive(false);
        stack.Remove(panel);
    }
}

常见坑

  • 面板缓存不释放/事件不退订，越玩越卡、越玩越容易空引用。
  • 每次打开都 Instantiate + 全屏布局，卡顿；用缓存/异步加载/分帧。
  • UI 每帧刷新文本/列表，触发 Canvas Rebuild；只在数据变化时刷新。
  • 分辨率/刘海/安全区没适配；按钮被挡住。

练习

给 PanelManager 加“返回栈/ESC 关闭”；把登录/注册面板改成事件驱动；用 Frame Debugger 看打开面板时的 Canvas 批次。

2026 更新：UGUI + TMP 仍是主流；UI Toolkit 适合工具/数据界面；MVVM/UniRx/消息总线可解耦；异步加载/安全区/无障碍/本地化要纳入设计；避免每帧刷新 UI。

本章要点：UI = BasePanel + PanelManager；层级/缓存/生命周期/事件订阅；登录/注册/提示/大厅/房间/战斗面板；UI 订阅网络事件而不是轮询。
