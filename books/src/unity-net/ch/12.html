第 12 章 同步战斗信息

原书讲同步理论：同步的过程/难题；状态同步（直接状态、跟随算法、预测算法）；帧同步（指令同步、从 Update 说起、同步帧、指令/执行）；协议（SyncTank/Fire/Hit）；服务端处理；细节（滚动的轮子/履带、灵活操作、准心、自动瞄准、界面/场景优化、战斗面板、击杀提示）。

状态同步是“服务端发状态，客户端跟随/插值/预测”；帧同步是“服务端发指令，客户端按同一帧执行”。状态同步更适合服务器权威的 FPS/动作游戏；帧同步更适合 RTS/格斗/需要确定性的场景。

同步的难点是延迟、丢包、抖动、作弊、带宽。预测/回滚/延迟补偿/插值/兴趣管理是常见手段。

关键实现：插值 + 预测

状态同步的客户端通常做三件事：对远端实体做插值（平滑）、对本地实体做预测（低延迟）、收到服务器校正时做和解（避免瞬移）。预测不是“客户端说了算”，而是“先表现、再被服务器纠正”。

public class SyncTank : MonoBehaviour
{
    public Vector3 serverPos;
    public Quaternion serverRot;
    public float interpolation = 12f;

    void Update()
    {
        // 远端：向服务器状态插值
        transform.position = Vector3.Lerp(transform.position, serverPos, interpolation * Time.deltaTime);
        transform.rotation = Quaternion.Slerp(transform.rotation, serverRot, interpolation * Time.deltaTime);
    }

    public void OnServerState(Vector3 pos, Quaternion rot)
    {
        serverPos = pos;
        serverRot = rot;
    }
}

常见坑

  • 预测过度/校正太硬，玩家看到“回拉/瞬移”；用平滑/误差阈值。
  • 同步频率过高，带宽爆炸；按距离/兴趣/重要性降频。
  • 帧同步不保证确定性（浮点/物理/随机数），不同设备结果分叉。
  • 只同步位置不同步朝向/炮塔/动画状态，表现不一致。

练习

对比 10/20/30 Hz 同步的带宽与手感；给远端坦克加插值缓冲；模拟 200ms 延迟，观察预测/校正。

2026 更新：现代动作游戏用 tick-based 快照 + 客户端预测/回滚 + 延迟补偿 + 兴趣管理；帧同步要保证确定性（定点数/固定物理/随机种子）；带宽/丢包/抖动要用插值/冗余/拥塞控制。

本章要点：同步 = 状态同步/帧同步；状态同步服务端权威 + 插值/预测；帧同步指令 + 确定性执行；延迟/丢包/作弊/带宽是难点；现代用快照/预测/回滚/延迟补偿。
