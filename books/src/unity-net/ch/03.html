第 3 章 实践：大乱斗游戏与协议

原书用一个“大乱斗”小游戏把网络模块跑起来：角色、场景、进入游戏、玩家列表、移动、离开、攻击、受击、死亡。每个动作对应一个协议（消息），客户端发送意图，服务端校验/广播结果。

协议设计的核心是“消息 ID + 参数 + 序列化”。消息要能区分类型（Enter/List/Move/Leave/Attack/Hit/Die），要有玩家 ID、位置、方向、时间戳等字段；服务端不能盲信客户端，要校验移动速度、攻击范围、冷却和命中。

这一章把“Socket 能通”推进到“游戏能玩”：消息顺序、状态同步、事件广播、断线处理开始变得重要。

2026 更新：现代协议多用 Protobuf/MessagePack/FlatBuffers，带 schema 版本和向后兼容；消息要幂等、可重放、可限流。动作游戏通常不用纯 TCP 广播，而是 UDP/ENet/UTP + 快照/预测；防作弊必须服务端权威。

本章要点：每个动作一个协议；消息 ID + 参数 + 序列化；服务端校验移动/攻击/命中；消息顺序/广播/断线；服务端权威。
