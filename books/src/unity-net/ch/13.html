附录 2026：从自定义 Socket 到现代网络栈

原书的自定义 Socket 是很好的学习脚手架：你能看到连接、粘包、心跳、协议、服务端框架、房间、战斗、同步的全过程。但生产环境很少从零写 Socket：更常见的是用成熟传输层/网络框架，把精力放在游戏逻辑、权威校验、匹配、运维和反作弊上。

选型要看游戏类型：回合制/大厅可用 TCP/WebSocket/HTTP；实时动作可用 UDP/ENet/UTP/QUIC；Unity 官方有 Netcode for GameObjects + Unity Transport；社区有 Mirror/FishNet；托管有 Photon/Nakama/PlayFab；大规模专用服务器有 GameLift/Agones。

生产清单：鉴权/TLS、服务端权威、限流/防刷、可观测性、压测、部署/扩容、成本、断线重连、版本兼容、数据持久化。

迁移路线

如果今天从原书的自定义 Socket 迁移，建议分三步：先保留协议/业务层，把传输层换成成熟方案；再把服务端拆成“网关 + 游戏服 + 数据层”；最后补鉴权、限流、可观测性和压测。不要一次性重写所有模块。

场景优先方案理由
回合制/大厅/聊天TCP / WebSocket / HTTP可靠、易调试、服务器压力可控。
实时动作/FPSUDP / ENet / Unity Transport / QUIC低延迟、可丢帧、支持预测/回滚。
Unity 官方路线Netcode for GameObjects + Unity Transport与 Unity 集成好，适合中小项目。
社区框架Mirror / FishNet成熟、资料多、可定制。
托管后端Photon / Nakama / PlayFab省运维，按量付费。
专用服务器GameLift / Agones / Kubernetes大规模、可弹性伸缩。

上线检查清单

  • 鉴权：登录 token、过期/刷新、顶号/踢人。
  • 传输：TLS/DTLS、证书、重连/退避、心跳。
  • 权威：移动/攻击/命中/经济由服务端校验。
  • 防刷：限流、验证码、冷却、异常检测。
  • 可观测：日志/指标/追踪/告警/战斗回放。
  • 压测：连接数、广播、房间创建、数据库慢查询。
  • 部署：容器化、灰度、回滚、备份、灾备。
  • 成本：带宽、CPU、数据库、托管服务费用。

练习

给一个“回合制卡牌 + 实时观战”的项目选型，写出传输层、服务端框架、数据库、部署方案，并说明为什么。

2026 更新：Unity 6 推荐 Netcode for GameObjects + Unity Transport（或第三方）；WebGL 用 WebSocket/WebRTC；生产要加 TLS、鉴权、限流、可观测性、压测、容器化、灰度/回滚。原书的 Socket 知识仍然有用：理解底层才能排查粘包、延迟、断线、同步问题。
