第 6 章 通用客户端网络模块

原书把客户端网络能力抽成“通用模块”：对外提供 Connect/Close/Send/事件回调，内部管理 Socket、收发包、心跳、协议编解码。业务层不直接碰 Socket，只订阅“连接成功/断开/收到消息”。

模块设计要点：连接状态机（未连接/连接中/已连接/关闭中）、消息队列、主线程分发、超时/重连、心跳 PING/PONG、序列化（JSON/Protobuf）、错误回调。网络线程只做 I/O，Unity 主线程消费事件。

这一章的核心是“把网络细节关进盒子里”：业务代码只关心协议和事件，不关心 Socket 生命周期。

关键实现：NetManager 骨架

业务层只看到 Connect/Close/Send/OnMessage；内部用状态机管理连接，用队列把网络线程的数据交给主线程。连接状态建议显式建模：Disconnected / Connecting / Connected / Closing。

public enum NetState { Disconnected, Connecting, Connected, Closing }

public class NetManager
{
    public NetState State { get; private set; }
    public event Action OnConnected;
    public event Action<string> OnDisconnected;
    public event Action<MsgBase> OnMessage;

    readonly ConcurrentQueue<MsgBase> mainQueue = new();

    public void Update() // 主线程每帧调用
    {
        while (mainQueue.TryDequeue(out var msg))
            OnMessage?.Invoke(msg);
    }

    public async Task ConnectAsync(string host, int port)
    {
        State = NetState.Connecting;
        // ... ConnectAsync / 启动读循环 ...
        State = NetState.Connected;
        OnConnected?.Invoke();
    }
}

常见坑

  • 事件订阅没有退订，场景切换后旧对象仍被回调（内存泄漏/空引用）。
  • 连接中重复点“登录”发起多次 Connect；需要状态机/按钮禁用。
  • JSON 用反射序列化在 IL2CPP/AOT 下受限；提前测试或换 MessagePack/Protobuf。
  • 心跳/重连和业务消息共用一条队列，断线时顺序错乱。

练习

给 NetManager 加“请求-响应”模式：每条请求带 seq，超时回调失败；再加重连后自动重新登录。

2026 更新：现代客户端可用 System.Text.Json/MessagePack、Channel<Message>、UniTask/Awaitable、CancellationToken；WebSocket/Unity Transport 替代裸 TCP；重连要指数退避 + 幂等登录。

本章要点：客户端模块封装 Connect/Close/Send/事件；状态机/队列/主线程分发/心跳/重连/序列化；业务只订阅事件，不碰 Socket。
