第 11 章 战斗和胜负判定

原书把战斗拆成协议（进入战斗、战斗结果、退出战斗）、坦克/战斗管理器、出生点、服务端开启战斗、胜负判断、断线处理、结果面板。服务端决定“能不能开始、谁赢了、何时结束”，客户端负责表现。

战斗流程：房间满足条件 → 服务端分配出生点/阵营 → 进入战斗 → 同步移动/开火/命中 → 一方全灭/时间到/目标达成 → 结算 → 返回房间/大厅。断线要区分“短暂掉线”和“退出”，并处理重连/托管/判负。

这一章的核心是“权威结算”：伤害、击杀、胜负不能由客户端说了算。

原书脉络

  • 11.1 协议设计：进入战斗/战斗结果/退出战斗。
  • 11.2 坦克；11.3 战斗管理器；11.4 战斗结果面板；11.5 服务端开启战斗。
  • 11.6 服务端胜负判断；11.7 断线处理；11.8 测试。

关键实现：服务端胜负判定

服务端维护每个玩家的血量/存活/队伍；每次伤害结算后检查“某队全灭/时间到/目标达成”，只结算一次，结果落库并广播。断线要区分“暂时掉线”和“退出”，给重连窗口或托管。

public class BattleManager
{
    public readonly List<PlayerData> Players = new();
    public bool Finished;

    public void OnDamage(int targetId, int damage)
    {
        var p = Players.First(x => x.Id == targetId);
        p.Hp = Math.Max(0, p.Hp - damage);
        if (p.Hp == 0) p.Alive = false;
        CheckWin();
    }

    void CheckWin()
    {
        if (Finished) return;
        var aliveTeams = Players.Where(p => p.Alive).Select(p => p.Team).Distinct().ToList();
        if (aliveTeams.Count <= 1)
        {
            Finished = true;
            // 广播 MsgBattleResult，落库，回房间/大厅
        }
    }
}

常见坑

  • 客户端上报“我赢了”；服务端必须自己算。
  • 伤害/死亡重复结算；用幂等/战斗 ID。
  • 断线玩家仍占位/仍可被击中；定义重连/托管/判负规则。
  • 结算后客户端还在发消息；关闭战斗会话/忽略旧消息。

练习

加“时间上限/击杀数”两种胜负条件；给断线玩家 30 秒重连窗口；写一个战斗结果落库的接口。
