第 1 章 网络游戏的开端：Echo、Socket 与 TCP/UDP

网络游戏的第一步不是“写个大厅”，而是让两台机器能可靠地交换一段字节。原书用 Echo 程序开篇：客户端发什么，服务端就回什么。它把“服务端/客户端、IP、端口、Socket、TCP/UDP、公网/局域网”这些概念放进一个最小可运行的例子里。

Socket 可以理解为“IP + 端口 + 协议”的通信端点。TCP 是字节流：连接建立后，双方按顺序收发字节，没有消息边界；UDP 是数据报：每个包独立、可能丢失/乱序，但延迟低。Echo 程序通常用 TCP，因为“发出去、收回来”最容易验证。

客户端用 Connect 连接服务端，服务端用 Bind + Listen + Accept 接受连接；之后双方用 Send/Receive 读写。公网/局域网、NAT、防火墙、端口映射决定了“为什么同一台电脑能连、换台手机就连不上”。

关键实现：最小 Echo

先写服务端：监听端口、接受连接、读一段、原样写回。再写客户端：连接、发送、读取、关闭。真实项目要加异常处理、超时、取消和日志，但最小版本先把“连接—收发—关闭”跑通。

// 服务端（简化）
var listener = new TcpListener(IPAddress.Any, 9000);
listener.Start();
while (true)
{
    using var client = await listener.AcceptTcpClientAsync();
    using var stream = client.GetStream();
    var buffer = new byte[1024];
    int n = await stream.ReadAsync(buffer, 0, buffer.Length);
    if (n > 0) await stream.WriteAsync(buffer, 0, n);
}

// 客户端（简化）
using var client = new TcpClient();
await client.ConnectAsync("127.0.0.1", 9000);
using var stream = client.GetStream();
var data = Encoding.UTF8.GetBytes("hello");
await stream.WriteAsync(data, 0, data.Length);
var buffer = new byte[1024];
int n = await stream.ReadAsync(buffer, 0, buffer.Length);
Console.WriteLine(Encoding.UTF8.GetString(buffer, 0, n));

常见坑

  • 在 Unity 主线程里同步 Connect/Receive，导致卡死；至少用异步或子线程。
  • 只测 127.0.0.1，没测局域网/公网/NAT；换设备就连不上。
  • 忘记 using/Close，端口/句柄泄漏；ReuseAddress 不是万能药。
  • 把“TCP 连接成功”当成“登录成功”，缺少应用层握手/鉴权。

练习

把 Echo 改成“多客户端回显 + 客户端 ID”；用 Stopwatch 测一次往返延迟；再用 Wireshark 看 TCP 三次握手和 FIN。

2026 更新：WebGL 不能直接用裸 TCP Socket，要用 WebSocket/WebRTC/Unity Transport；桌面/移动端仍可用 System.Net.Sockets。生产环境还要加 TLS、鉴权、超时和重连；IPv6/NAT 穿透/中继要提前设计。

本章要点：Socket = IP + 端口 + 协议；TCP 字节流、UDP 数据报；客户端 Connect、服务端 Bind/Listen/Accept；公网/局域网/NAT 决定连通性；WebGL 需换传输层。
