着色器（Shaders）

本节面向这样的用户：希望把已有的自定义着色器（shader）改造成能在 URP 中工作，和/或希望不使用 Shader Graph、直接用代码编写自定义着色器。本节提供了把基础着色器与高级着色器从内置渲染管线（Built-in Render Pipeline）移植到 URP 所需的信息。文中包含的表格给出了可用的 HLSL 着色器函数、宏等的实用示例；每一处都提供了指向相应 include 文件的链接，而那些 include 文件中还包含许多其他有用的函数。

对于已经具备着色器编写经验的读者，这些 include 文件可以让你清楚地了解 HLSL 中都有什么可用，从而写出紧凑而高效的着色器。在了解本节的内容之后，希望把你的着色器移植到 URP 不再显得那么令人生畏。

另一种做法是使用 Shader Graph 来创建自定义着色器的各个版本。Shader Graph 的入门介绍位于「其他工具（Additional tools）」一节。

SubShader 块的基本结构

在把 URP 着色器与内置渲染管线着色器作比较时，首先会注意到的是 SubShader 标签中使用了键值对 "RenderPipeline" = "UniversalPipeline"。

SubShader {
   Tags {"RenderPipeline" = "UniversalPipeline" }
   Pass {
      HLSLPROGRAM
      ...
      ENDHLSL
   }
}

名为 RenderPipeline 的 SubShader 标签告诉 Unity 该 SubShader 要用于哪些渲染管线。值 UniversalPipeline 表示 Unity 应将该 SubShader 用于 URP。

再看渲染 Pass 的代码，你会看到着色器代码被包含在 HLSLPROGRAM / ENDHLSL 宏之间。这表明原先的 CG（C for Graphics）着色器编程语言已被 HLSL（High Level Shading Language，高级着色语言）取代，尽管着色器语法和功能几乎完全相同。Unity 很久以前就已切换到 HLSL，所以这不应让人感到意外，但现在不再推荐使用 CGPROGRAM / ENDCG 宏。使用这些宏意味着要使用 UnityCG.cginc。以这种方式混用 SRP 与内置渲染管线的着色器库，可能引发若干问题。

对于 URP，这些 Pass 内部的着色器代码是用 HLSL 编写的。尽管与内置渲染管线相比，ShaderLab 的大部分内容并未改变，但为内置渲染管线编写的着色器会被 URP 自动禁用。原因在于内部光照流程的变化。内置渲染管线会为到达物体的每一盏光源执行单独的着色器 Pass（多 Pass，multipass），而 URP 的前向渲染器（Forward Renderer）则在一个 Pass 内的光照循环中计算全部光照。这一变化带来了存储光照数据的不同数据结构，以及采用新约定的新的着色库。

Unity 会使用 GPU 上受支持的第一个 SubShader 块。如果第一个 SubShader 块没有 "RenderPipeline" = "UniversalPipeline" 标签，它就不会在 URP 中运行。此时 Unity 会尝试运行下一个 SubShader（如果有的话）。如果所有 SubShader 都不受支持，Unity 就会渲染那个众所周知的品红色错误着色器。

一个 SubShader 可以包含多个 Pass 块，但其中每一个都应标记特定的 LightMode。由于 URP 使用单 Pass 的前向渲染器，在前向渲染中只会使用 GPU 所支持的第一个 UniversalForward Pass 来渲染物体。

其他有用的 HLSL include 文件

与空间变换相关的函数位于这个 include 文件中，当你使用 Core.hlsl 时，它会默认被添加。

HLSL 空间变换函数 说明
float4x4 GetObjectToWorldMatrix() 返回从物体空间（Object Space）转换到世界空间（World Space）的 UNITY_MATRIX_M 矩阵。

它等价于内置渲染管线的 unity_ObjectToWorld。
float4x4 GetWorldToObjectMatrix() 返回从世界空间转换到物体空间的 UNITY_MATRIX_I_M 矩阵。

该矩阵是 UNITY_MATRIX_M 的逆矩阵。它等价于内置渲染管线的 unity_WorldToObject。
float4x4 GetWorldToHClipMatrix() 返回从世界空间转换到裁剪空间（Clip Space）的 UNITY_MATRIX_VP 矩阵。
float4x4 GetViewToHClipMatrix() 返回从观察空间（View Space）转换到裁剪空间的 UNITY_MATRIX_P 矩阵。
float3 TransformObjectToWorld(float3 positionOS) 给定物体空间中的一个位置，返回该位置在世界空间中的位置。
float3 TransformObjectToWorldDir(float3 dirOS, bool doNormalize = true) 给定物体空间中的一个方向，返回该方向在世界空间中的方向。
float3 TransformWorldToObject(float3 positionWS) 给定世界空间中的一个位置，返回该位置在物体空间中的位置。
float3 TransformWorldToView(float3 positionWS) 给定世界空间中的一个位置，返回该位置在观察空间中的位置。
real3x3 CreateTangentToWorld(real3 normal, real3 tangent, real flipSign) 给定法线与切线，创建一个从切线空间（Tangent Space）到世界空间的矩阵。
real3 TransformTangentToWorld(real3 normalTS, real3x3 tangentToWorld, bool doNormalize = false) 给定切线空间中的法线，返回该法线在世界空间中的法线。
real3 TransformWorldToTangent(real3 normalWS, real3x3 tangentToWorld, bool doNormalize = true) 给定世界空间中的法线，返回该法线在切线空间中的法线。

变量名末尾表示空间类型的记法：

  • WS：世界空间（World Space）
  • TS：切线空间（Tangent Space）
  • VS：观察空间（View Space）
  • OS：物体空间（Object Space）

其他着色器函数（包括雾效和 UV）可以在这一 include 文件中找到，当你使用 Core.hlsl 时，它会默认被添加。下表列出了几个示例。

URP 辅助函数 说明
VertexPositionInputs GetVertexPositionInputs(float3 positionOS) 给定物体空间中的一个位置，返回一个包含世界空间、观察空间和裁剪空间中位置的结构体。

该函数只应在顶点着色器中使用。
VertexNormalInputs GetVertexNormalInputs(float3 normalOS) 给定物体空间中的一个法线，返回一个包含世界空间法线、切线和副切线（bitangent）向量的结构体。

这些向量可用于通过 CreateTangentToWorld 构造从切线空间到世界空间的矩阵。返回 input.tangentWS、input.bitangentWS、input.normalWS。
float3 GetCameraPositionWS() 返回摄像机在世界空间中的位置。

它类似于内置渲染管线的 _WorldSpaceCameraPos 变量。
float3 GetViewForwardDir() 返回当前视图在世界空间中的前向（中心）方向。
float3 GetWorldSpaceViewDir(float3 positionWS) 计算世界空间中的视线方向（指向观察者）。
