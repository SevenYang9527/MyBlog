命令模式（Command Pattern）

命令模式是四人组（Gang of Four）提出的原始设计模式之一，只要你需要追踪一系列特定动作，它就能派上用场。如果你玩过带有撤销/重做（undo/redo）功能、或者会把输入历史保存在列表里的游戏，那你很可能已经见过命令模式在工作了。想象一款策略游戏，用户可以在真正执行之前先规划好几个回合——这就是命令模式。

命令模式不直接调用某个方法，而是允许你把一个或多个方法调用封装成一个「命令对象（command object）」。

把这些命令对象存放在队列（queue）或栈（stack）之类的集合中，你就能控制它们执行的时机。这相当于一个小型缓冲区。于是你可以把一系列动作延迟到之后回放，或者将它们撤销。

要实现命令模式，你需要一个能容纳动作的通用对象。这个命令对象将持有「执行什么逻辑」以及「如何撤销它」。

命令对象与命令调用者（The command object and command invoker）

实现方式有很多种，下面是使用接口（interface）的一种写法：

用命令模式存储动作（Storing actions with the command pattern）

public interface ICommand
{
    void Execute();
    void Undo();
}

在这种情况下，每个玩法动作都会实现 ICommand 接口（你也可以用抽象类（abstract class）来实现）。

每个命令对象都负责自己的 Execute 和 Undo 方法。因此，往游戏里添加更多命令不会影响任何已有的命令。

你还需要另一个类来执行和撤销命令。创建一个 CommandInvoker 类。除了 ExecuteCommand 和 UndoCommand 方法之外，它还有一个撤销栈（undo stack），用来保存命令对象的序列。

public class CommandInvoker
{
    private static Stack<ICommand> undoStack = new Stack<ICommand>();
    public static void ExecuteCommand(ICommand command)
    {
        command.Execute();
        undoStack.Push(command);
    }
    public static void UndoCommand()
    {
        if (undoStack.Count > 0)
        {
            ICommand activeCommand = undoStack.Pop();
            activeCommand.Undo();
        }
    }
}

示例：可撤销的移动（Example: Undoable movement）

假设你想让玩家在应用程序的迷宫里四处移动。你可以创建一个 PlayerMover，由它负责改变玩家的位置：

public class PlayerMover : MonoBehaviour
{
    [SerializeField] private LayerMask obstacleLayer;
    private const float boardSpacing = 1f;
    public void Move(Vector3 movement)
    {
        transform.position = transform.position + movement;
    }
    public bool IsValidMove(Vector3 movement)
    {
        return !Physics.Raycast(transform.position, movement, boardSpacing, obstacleLayer);
    }
}

你向 Move 方法传入一个 Vector3，引导玩家沿着四个基本方向移动。你还可以使用射线检测（raycast），在相应的 LayerMask 中探测墙壁。当然，你想把什么内容套用到命令模式上，与模式本身是两回事。

要遵循命令模式，就把 PlayerMover 的 Move 方法捕获为一个对象。不要直接调用 Move，而是新建一个类 MoveCommand，让它实现 ICommand 接口：

public class MoveCommand : ICommand
{
    PlayerMover playerMover;
    Vector3 movement;
    public MoveCommand(PlayerMover player, Vector3 moveVector)
    {
        this.playerMover = player;
        this.movement = moveVector;
    }
    public void Execute()
    {
        playerMover.Move(movement);
    }
    public void Undo()
    {
        playerMover.Move(-movement);
    }
}

ICommand 需要一个 Execute 方法来存放你想完成的事情。你想实现的任何逻辑都写在这里，所以这里用移动向量调用 Move。

ICommand 还需要一个 Undo 方法，把场景恢复到之前的状态。在这个例子里，撤销逻辑是减去移动向量，本质上就是把玩家推向相反的方向。

MoveCommand 会保存它执行时所需的任何参数。这些参数通过构造函数（constructor）设置。在这个例子里，你保存了对应的 PlayerMover 组件和移动向量。

创建好命令对象并保存其所需参数之后，使用 CommandInvoker 的静态方法 ExecuteCommand 和 UndoCommand 传入你的 MoveCommand。这会运行 MoveCommand 的 Execute 或 Undo，并在撤销栈中追踪该命令对象。

InputManager 不会直接调用 PlayerMover 的 Move 方法。相反，它额外增加一个方法 RunMoveCommand，用来创建新的 MoveCommand 并把它发送给 CommandInvoker。

private void RunPlayerCommand(PlayerMover playerMover, Vector3 movement)
{
    if (playerMover == null)
    {
        return;
    }
    if (playerMover.IsValidMove(movement))
    {
        ICommand command = new MoveCommand(playerMover, movement);
        CommandInvoker.ExecuteCommand(command);
    }
}

然后，设置 UI 按钮上的各个 onClick 事件，让它们用四个移动向量调用 RunPlayerCommand。

查看示例项目以了解 InputManager 的实现细节，或者用键盘、手柄搭建你自己的输入。现在你的玩家可以在迷宫里穿行了。点击 Undo 按钮，就能回溯到起始格。

优点与缺点（Pros and cons）

要实现可重放或可撤销，只需生成一组命令对象即可。你还可以利用命令缓冲区（command buffer），在特定控制下按顺序回放动作。

举例来说，想一想格斗游戏：一系列特定的按键点击会触发一个连招（combo move）或攻击。用命令模式存储玩家动作，可以让这类连招的设置简单得多。

反过来看，和其他设计模式一样，命令模式会引入更多结构。你必须判断这些额外的类和接口，是否值得你在应用程序中部署命令对象。

改进（Improvements）

掌握了基础之后，你就可以根据具体情境去影响命令的时机，让它们接连回放或者反向播放。

在引入命令模式时，可以考虑以下几点：

  • 创建更多命令：示例项目只包含一种命令对象，即 MoveCommand。你可以创建任意数量实现 ICommand 的命令对象，并用 CommandInvoker 追踪它们。
  • 添加重做功能无非是再加一个栈：撤销某个命令对象时，把它压入另一个栈，由该栈追踪重做（redo）操作。这样你就能快速在撤销历史中来回切换，或者重做那些动作。当用户发起一个全新的移动时，清空重做栈（你可以在附带的示例项目中找到实现）。
  • 为命令对象缓冲区换用其他集合：如果你想要先进先出（FIFO）的行为，队列可能更顺手。如果使用列表，就记录当前活动的索引；位于活动索引之前的命令可撤销，位于该索引之后的命令可重做。
  • 限制栈的大小：撤销和重做操作很快就会膨胀到失控。把栈限制为最近若干条命令。
  • 把任何必要的参数传入构造函数：这有助于像 MoveCommand 示例那样封装逻辑。CommandInvoker 和其他外部对象一样，看不到命令对象的内部运作，只会调用 Execute 或 Undo。在调用构造函数时，把命令对象工作所需的任何数据交给它。
