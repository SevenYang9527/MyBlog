一份 2018 年的讲义，为什么还值得读

《UGUI 原理和优化》是一份 34 页的技术讲义，封面署名何冠峰（文西）。PowerPoint 内部元数据记录的创建时间是 2018 年 8 月 30 日，最后修改时间是 2019 年 7 月 23 日；文件系统里的修改时间则是 2022 年 2 月 27 日，很可能是后来复制或另存造成的，不能据此判断内容在 2019 年后又被改过。因此，本书把它当作一份 Unity 2018/2019 时代的分享来读，并在涉及版本差异时单独说明。

这个时间点很重要。那时 UGUI 还是 Unity 运行时 UI 的绝对主力，TextMeshPro 还没有像今天这样成为默认文本方案，UI Toolkit 也还没有运行时版本。讲义里的大量结论来自当时的官方文档、引擎源码和项目经验；其中有些今天仍然成立，有些需要补充，有些则已经过时。

本书不是把讲义逐字翻译一遍，而是把它当作一份“待核对的底稿”：先还原它想表达的技术模型，再对照 Unity 官方文档与 com.unity.ugui 源码，逐条判断真假；最后用今天的版本重写一遍。讲义里那些仍然有效的判断会被保留，错误或过时的部分会被明确标出。本书不复制原讲义的图片和整段文字，只保留必要的短语用于核对；技术结论以文档、源码和可复现的工程验证为准。

讲义里混着三种东西

读这类技术分享，最容易犯的错误是把所有句子都当成同一等级的“事实”。这份讲义里至少混着三种内容：

  • 引擎事实：例如 Canvas 的绘制顺序、RectTransform 中 sizeDelta 的含义、Rebuild 由谁触发。这些可以用文档和源码验证，对错比较清楚。
  • 性能经验：例如“动静 UI 分 Canvas”“关闭不用的 Raycast”“少用 Tiled Image”。方向通常是对的，但收益取决于项目规模、目标平台和具体实现，不能当成绝对值。
  • 项目案例：例如讲义里提到的《龙与少女》优化方案、团队的美术规范、模板覆盖率。这些是分享者在特定项目里的做法，本书无法复现其工程现场，只核对其中可验证的技术机制；无法验证的部分会标成“经验之谈”。

所以，本书的判断不会只有“真”和“假”两种。更常见的情况是“方向对，但需要补充条件”，或者“在 2018 年成立，今天需要改写”。

本书的核对方法

核对流程分四步：先把 34 页讲义拆成可判断的句子；再按主题归类；然后查 Unity 手册、脚本 API、uGUI 源码和官方优化指南；最后给出判定，并把结论改写成今天可执行的版本。

版本基线

技术结论必须带版本。本书的默认基线是 Unity 2022.3 LTS（对应 com.unity.ugui 1.0.0）与 Unity 6（对应 com.unity.ugui 2.x；2.0.0 起合并了 TextMeshPro 包）。涉及旧版本差异时会单独说明。你在更老的 Unity 版本里读到的行为可能不同，尤其是字体、UI Toolkit、Canvas 批处理和多线程相关的细节。

对象本书采用的基线需要特别注意
UGUI / Unity UIUnity 2022.3 LTS（com.unity.ugui 1.0.0）与 Unity 6（com.unity.ugui 2.x）UGUI 仍然受支持，没有被 UI Toolkit 取代；2.0.0 起合并了 TextMeshPro 包；源码在 GitHub 的 Unity-Technologies/uGUI。
UI Toolkit运行时 UI 自 Unity 2021.2 起可用它原名 UIElements，最早在 2019.1 主要服务 Editor；讲义里“UI Element 是 Unity 2019 最新 UI 系统”的说法已经过时。
文本新项目优先 TextMeshPro（TMP）；旧项目可能仍用 UnityEngine.UI.Text两者字体图集、描边阴影、Best Fit 的成本模型不同，不能混着套结论。
源码uGUI GitHub main 分支与 Unity 包缓存不同 Unity 版本的包源码会有差异；排查时应以项目 Library/PackageCache 里的版本为准。

先看结论：最需要改掉的八个说法

为了避免你带着旧结论读完整本书，这里先列出最关键的八处订正。详细依据在对应章节和最后的勘误总表里。

讲义说法本书判定更准确的说法
UGUI 支持多线程（UI 重建）不准确Canvas 的批次计算和几何 Job 可以多线程；C# 侧的 Layout / Graphic Rebuild 仍在主线程。
UI Element 是最新 UI 系统（Unity 2019）过时它后来叫 UI Toolkit；运行时 UI 从 Unity 2021.2 才正式可用。
通过修改 Canvas 的 Layer 隐藏面板不通用，Overlay 下不成立Screen Space - Overlay 不受相机 Culling Mask 影响；要隐藏整块面板，优先禁用 Canvas 组件或 GameObject。
描边和阴影都会增大四倍顶点假Shadow 约 2 倍顶点，Outline 约 5 倍顶点（原始 1 份 + 4 个方向各 1 份）。
后备字体取自系统 Arial.ttf，安装包里没有不准确默认字体是 Arial；缺失时 Unity 会回退到自带的 Liberation Sans 或系统字体；WebGL / 主机不能依赖 OS 字体，必须把字体数据打进包。
锚框不能超过父矩形不准确编辑器拖动时默认限制在父矩形内，但按住快捷键、直接输入数值或在代码里都可以让 anchorMin/Max 超出 0~1。
修改 Size、Anchors、Pivot 都会改变 UIVertex.position不准确尺寸变化会重建顶点；纯位置变化不会改本地顶点；Anchors / Pivot 只有在改变矩形尺寸或局部矩形原点时才需要重建。
Canvas 下所有 UI 最终合批到同一个 Mesh大体真，但容易误解一个 Canvas 生成一个组合 Mesh，但其中按材质/纹理分成多个 SubMesh，也就是多个 DrawCall；不是所有元素都能合。

考据结论：这份讲义不是“官方规范”，而是一份带有强项目经验的技术分享。它的价值在于把 Canvas、RectTransform、Rebuild、合批、Overdraw、字体和 ScrollView 串成了一条完整的性能链路；它的风险在于部分结论是 2018 年的版本经验，不能无条件搬到今天。
