万维网、安全、黑客与加密：连接之后，如何信任

第三十到三十三集讲“互联网之上”的世界：万维网让信息可以互相链接，安全/黑客/加密则回答“怎么防止别人偷看、篡改、冒充”。这一章的主线是：连接带来便利，也带来攻击面；信任需要机制，而不是口号。

万维网：超文本 + 浏览器

万维网的核心是“超文本”：文档之间用链接互相引用。URL 定位资源，HTTP 传输请求/响应，HTML 描述结构，浏览器负责解析、渲染和交互。搜索引擎用爬虫、索引和排序算法，把“找网页”变成“搜关键词”。

概念作用
URL定位资源（协议 + 域名 + 路径 + 查询）
HTTP请求方法、状态码、头、正文
HTML/CSS/JS结构、样式、行为
Cookie/Session在无状态 HTTP 上维持登录状态

安全的基本目标

  • 机密性：别人看不到内容（加密）。
  • 完整性：内容没被篡改（哈希/签名/MAC）。
  • 认证：确认对方是谁（密码、证书、多因素、生物识别）。
  • 授权：确认对方能做什么（权限、最小权限原则）。
  • 可用性：服务在攻击/故障下仍可用（备份、限流、DDoS 防护）。

常见攻击

  • 恶意软件：病毒、蠕虫、木马、勒索软件。
  • 网络攻击：DDoS、中间人、DNS 劫持、ARP 欺骗。
  • Web 攻击：SQL 注入、XSS、CSRF、路径遍历。
  • 社会工程：钓鱼、冒充、诱导授权。
  • 漏洞利用：缓冲区溢出、零日、供应链投毒。

加密：对称、非对称与哈希

对称加密用同一把钥匙加解密（AES），快但需要安全地分发钥匙；非对称加密用公钥/私钥（RSA/ECC），解决密钥交换和签名；哈希把任意数据映射成固定长度指纹，用于完整性校验和密码存储（加盐 + 慢哈希）。

HTTPS 把两者结合：用非对称/密钥交换建立共享密钥，再用对称加密传输数据；证书和 CA 解决“公钥属于谁”的问题。数字签名则用私钥签名、公钥验证，保证来源和完整性。

2026 补充：TLS 1.3 简化握手、默认前向保密；Passkeys/WebAuthn 用公钥替代密码，降低钓鱼风险；零信任架构强调“永不默认信任、持续验证”。同时，后量子密码（PQC）迁移、供应链攻击和 AI 生成钓鱼成为新的安全议题。

本章要点：万维网 = 超文本 + URL + HTTP + 浏览器；安全目标是机密性/完整性/认证/授权/可用性；攻击面覆盖恶意软件、网络、Web、社会工程和供应链；HTTPS 用证书、密钥交换、对称加密和哈希建立信任。
