算法与数据结构：把“能算”变成“算得动”

第十三、十四集讲算法和数据结构。它们回答的是同一个问题的两面：算法是“解决问题的步骤”，数据结构是“把数据摆成什么形状”。选错数据结构，算法再聪明也会被拖慢；选对结构，很多问题会突然变简单。

算法的核心问题

  • 排序：选择排序、插入排序、归并排序、快速排序；从 O(n²) 到 O(n log n)。
  • 查找：线性查找 O(n)，二分查找 O(log n)（要求有序）。
  • 图遍历：BFS 找最短步数，DFS 找连通性/路径。
  • 最短路径：Dijkstra 适合非负权，Bellman-Ford 可处理负权。
  • 递归/分治/动态规划：把大问题拆小，避免重复计算。

Big-O：忽略常数，抓住增长趋势

Big-O 描述输入规模 n 变大时，运行时间/空间的上界。它不是精确计时，而是比较算法在规模增长下的“形状”。

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)

实际工程里还要看常数、缓存友好性、数据分布和实现质量；O(n log n) 的排序不一定总比插入排序快，尤其在小数组上。

常见数据结构

结构优点代价/适用
数组随机访问 O(1)，缓存友好插入/删除中间元素 O(n)
链表插入/删除 O(1)（已知位置）随机访问 O(n)，指针开销
栈/队列后进先出/先进先出，简单高效只能按规则访问
哈希表平均 O(1) 查找/插入冲突、扩容、最坏 O(n)
树/堆有序、范围查询、优先队列平衡维护成本
图表达关系/网络遍历和存储开销

2026 补充：现代系统里，数据结构的选择还受硬件影响：缓存友好的数组/紧凑布局常常比“理论更优”的指针结构更快；大规模数据会用 B 树/LSM 树、布隆过滤器、倒排索引、向量索引（HNSW/IVF）等专用结构。

本章要点：算法是步骤，数据结构是形状；Big-O 看增长趋势；排序/查找/图算法是基础工具箱；数组、链表、栈队列、哈希表、树、图各有取舍；工程上要同时考虑常数、缓存和数据分布。
