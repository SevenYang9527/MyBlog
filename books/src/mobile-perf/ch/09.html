用户界面（User Interface）

Unity 提供两套 UI 系统：较旧的 Unity UI 和较新的 UI Toolkit。UI Toolkit 的目标是成为推荐的 UI 系统。它专为实现最高性能和可复用性而设计，其工作流和创作工具灵感来自标准 Web 技术，这意味着如果 UI 设计师和美术师已有网页设计经验，会感到十分熟悉。

不过，截至 Unity 2022 LTS，UI Toolkit 尚未具备 Unity UI 和即时模式 GUI（Immediate Mode GUI，IMGUI）所支持的一些功能。在某些使用场景下，Unity UI 和 IMGUI 更为合适，并且是支持旧项目所必需的。更多信息请参阅 Unity 中 UI 系统的比较。

UGUI 性能优化建议（UGUI performance optimization tips）

Unity UI（UGUI）常常是性能问题的来源。Canvas 组件会为 UI 元素生成并更新网格（mesh），并向 GPU 发出绘制调用（draw call）。它的运作开销可能很高，因此在使用 UGUI 时请留意以下因素。

拆分 Canvas（Divide your Canvases）

如果你有一个包含数千个元素的大型 Canvas，那么更新单个 UI 元素就会迫使整个 Canvas 更新，可能造成 CPU 峰值。请利用 UGUI 支持多个 Canvas 的能力。根据 UI 元素需要刷新的频率来拆分它们。将静态 UI 元素放在单独的 Canvas 上，并将同时更新的动态元素放在较小的子 Canvas 上。

确保每个 Canvas 内的所有 UI 元素具有相同的 Z 值、材质（material）和纹理（texture）。

隐藏不可见的 UI 元素（Hide invisible UI elements）

有些 UI 元素可能只在游戏中偶尔出现（例如，只在角色受到伤害时才显示的血条）。如果你的不可见 UI 元素处于激活状态，它可能仍在使用绘制调用。请显式禁用任何不可见的 UI 组件，并在需要时重新启用它们。

如果你只需要关闭 Canvas 的可见性，请禁用 Canvas 组件，而不是整个 GameObject。这样可以避免游戏在重新启用它时必须重建网格和顶点。

限制 GraphicRaycaster 并禁用 Raycast Target

屏幕触摸或点击等输入事件需要 GraphicRaycaster 组件。它只是遍历屏幕上的每个输入点，并检查该点是否位于某个 UI 的 RectTransform 内。

从层级中最顶层的 Canvas 上移除默认的 GraphicRaycaster。相反，只把 GraphicRaycaster 添加到需要交互的各个元素上（按钮、scrollrect 等）。

禁用 Ignore Reversed Graphics，该选项默认处于启用状态。

此外，在所有不需要的 UI 文本和图像上禁用 Raycast Target。如果 UI 很复杂、包含许多元素，所有这些细小的改动都能减少不必要的计算。

避免使用 Layout Group（Avoid Layout Groups）

Layout Group 的更新效率低下，因此请尽量少用。如果你的内容不是动态的，就完全避免使用它们，而改用锚点（anchor）实现按比例布局。另一种做法是编写自定义代码，在 Layout Group 组件完成 UI 设置后将其禁用。

如果你确实需要为动态元素使用 Layout Group（Horizontal、Vertical、Grid），请避免嵌套使用，以提升性能。

避免大型 List 和 Grid 视图

大型 List 和 Grid 视图开销很高。如果你需要创建大型 List 或 Grid 视图（例如包含数百个物品的背包界面），请考虑复用一小组 UI 元素，而不是为每个物品都创建一个 UI 元素。可以查看这个示例 GitHub 项目，了解实际做法。

避免大量叠加元素（Avoid numerous overlaid elements）

将大量 UI 元素层层叠加（例如卡牌对战游戏中堆叠的卡牌）会造成过度绘制（overdraw）。请定制你的代码，在运行时将分层元素合并为更少的元素和批次（batch）。

使用多种分辨率和宽高比

如今移动设备使用的分辨率和屏幕尺寸差异很大，因此请创建 UI 的替代版本，以便为每台设备提供最佳体验。使用 Device Simulator 在各类受支持设备上预览 UI。你也可以在 XCode 和 Android Studio 中创建虚拟设备。

使用全屏 UI 时隐藏其他所有内容

如果你的暂停界面或开始界面覆盖了场景中其他所有内容，请禁用渲染 3D 场景的摄像机。同样，禁用隐藏在最顶层 Canvas 后面的任何背景 Canvas 元素。

考虑在全屏 UI 期间降低 Application.targetFrameRate，因为此时你不需要以 60 fps 更新。

为 World Space 和 Camera Space Canvas 指定摄像机

将 Event 或 Render Camera 字段留空会迫使 Unity 填入 Camera.main，这会带来不必要的开销。

如有可能，考虑为 Canvas 的 RenderMode 使用 Screen Space – Overlay，因为它不需要摄像机。

UI Toolkit 性能优化建议（UI Toolkit performance optimization tips）

相比 Unity UI，UI Toolkit 提供了更好的性能；它专为实现最高性能和可复用性而设计，并提供受标准 Web 技术启发的工作流和创作工具。它的关键优势之一是使用了一条专门为 UI 元素设计的高度优化的渲染管线。

以下是使用 UI Toolkit 优化 UI 性能的一些通用建议：

  • 使用高效的布局：所谓高效布局，是指使用 UI Toolkit 提供的布局组（layout group），例如 Flexbox，而不是手动定位和调整 UI 元素的大小。布局组会自动处理布局计算，可显著提升性能。它们确保 UI 元素按照指定的布局规则正确排列和设置尺寸。借助高效布局，你可以避免手动布局计算的开销，并获得一致且优化的 UI 渲染。
  • 避免在 Update 中执行高开销操作：尽量减少在 Update 方法中执行的工作量，尤其是 UI 元素创建、操作或计算这类繁重操作。请尽量少执行这些操作，或在初始化期间执行，因为 Update 方法每帧都会被调用一次。
  • 优化事件处理：注意事件的订阅，并在不再需要时取消注册。过多的事件处理会影响性能，因此请确保只订阅必要的事件。
  • 优化样式表（style sheet）：注意样式表中使用的样式类（style class）和选择器（selector）的数量。包含大量规则的大型样式表会影响性能。请保持样式表精简，避免不必要的复杂性。
  • 性能分析并优化：使用 Unity 的性能分析工具找出 UI 中的性能瓶颈，并发现可以进一步优化的方面，例如低效的布局计算或过多的重绘（redraw）。
  • 在目标平台上测试：在目标平台上测试 UI 性能，以确保在不同设备上都能获得最佳性能。性能会因硬件能力而异，因此在优化 UI 时请考虑目标平台。

请记住，性能优化是一个迭代过程。请持续对 UI 代码进行性能分析、测量和优化，以确保它流畅高效地运行。
