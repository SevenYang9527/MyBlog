更复杂的光照：多光源、衰减与阴影

原书第 9 章把“单光源 Blinn-Phong”扩展到真实项目：Unity 的渲染路径、光源类型、光照衰减、阴影，以及如何写一个能处理多光源和阴影的 Standard Shader。这一章是内置管线光照的分水岭。

Unity 的渲染路径

路径思路适用
Forward（前向）每个物体对每个光源执行一次光照 Pass；多光源时 Pass 数增加。光源不多、需要自定义光照、移动端常见。
Vertex Lit（顶点照明）光照在顶点阶段算，便宜但效果粗糙。低端设备、简单物体。
Deferred（延迟）先写 G-Buffer（法线/颜色/深度等），再统一做光照。光源多、桌面端；对透明/自定义 Shader 有限制。

渲染路径不是 Shader 里随便选的，而是由 Camera 的 Rendering Path 和项目设置决定。Shader 通过 LightMode 标签声明自己属于哪个 Pass。

光源类型与 Pass 标签

  • ForwardBase：处理环境光、主方向光、光照贴图、阴影。
  • ForwardAdd：处理额外的逐像素光源，通常每个光源一个 Pass。
  • ShadowCaster：渲染阴影贴图。
  • Vertex / VertexLMRGBM / VertexLM：顶点照明/光照贴图。

光照衰减

点光源和聚光灯的强度随距离衰减。内置管线可以用光照纹理（_LightTexture0）或数学公式计算衰减：

// 内置管线中常见的衰减宏
UNITY_LIGHT_ATTENUATION(atten, i, i.worldPos);
float3 lighting = (diffuse + specular) * atten;

平行光通常没有距离衰减，但可能有阴影衰减。点光/聚光的衰减纹理由 Unity 根据光源范围生成，直接采样比手写公式更接近内置结果。

阴影

实时阴影的核心是 shadow map：从光源视角渲染深度，再在相机视角比较深度。内置管线用 AutoLight.cginc 的宏封装了大部分细节：

#pragma multi_compile_fwdbase
#include "AutoLight.cginc"

struct v2f
{
    float4 pos : SV_POSITION;
    float3 worldPos : TEXCOORD0;
    float3 worldNormal : TEXCOORD1;
    SHADOW_COORDS(2)
};

v2f vert (appdata v)
{
    v2f o;
    o.pos = UnityObjectToClipPos(v.vertex);
    o.worldPos = mul(unity_ObjectToWorld, v.vertex).xyz;
    o.worldNormal = UnityObjectToWorldNormal(v.normal);
    TRANSFER_SHADOW(o);
    return o;
}

fixed4 frag (v2f i) : SV_Target
{
    float3 N = normalize(i.worldNormal);
    float3 L = normalize(_WorldSpaceLightPos0.xyz);
    float3 V = normalize(_WorldSpaceCameraPos - i.worldPos);
    float3 H = normalize(L + V);

    float3 diffuse = _LightColor0.rgb * _DiffuseColor.rgb * saturate(dot(N, L));
    float3 specular = _LightColor0.rgb * _SpecularColor.rgb
                    * pow(saturate(dot(N, H)), _Gloss);

    UNITY_LIGHT_ATTENUATION(atten, i, i.worldPos);
    return fixed4((diffuse + specular) * atten, 1.0);
}

阴影 Pass 还需要 ShadowCaster：很多内置 Shader 通过 Fallback 提供，手写 Shader 常用 UsePass "Legacy Shaders/VertexLit/SHADOWCASTER" 引用内置 Pass，或者自己写一个。原书会带你看 AutoLight.cginc 里的宏展开，理解“为什么加几行宏就能接收阴影”。

多光源的成本

前向渲染中，每个逐像素光源通常对应一个 ForwardAdd Pass，也就是额外的 Draw Call 和光照计算。光源越多，成本越高；移动端要限制逐像素光源数量，或者用顶点光/光照贴图/烘焙。

现代 Unity 备注：URP 的光照、阴影、Pass 标签和宏与内置管线完全不同；URP 使用 Lighting.hlsl、Shadows.hlsl、UniversalForward 等。不要在 URP 里直接使用 ForwardBase/ForwardAdd 的内置宏。

本章要点：前向/延迟/顶点照明各有取舍；ForwardBase 管主光和环境，ForwardAdd 管额外光源；衰减和阴影靠宏/纹理；多光源 = 多 Pass = 多成本；移动端要控制逐像素光源。
