数据局部性

CPU 等的不是算力，是内存。把要一起用的数据排在一起，速度能差一个数量级。

  • 30 分钟
  • 批次 3 · 按需查
  • DOTS / ECS · Jobs + Burst · NativeArray · SoA 布局

原文在解决什么

现代 CPU 一次读一整条缓存行（64 字节）。如果遍历时跳到内存各处去找对象，绝大部分带宽都浪费在这个「跳」上。

作者给的方案：按需拆分数据（SoA，把同类字段排成数组）、热/冷分离（常用的字段单独放）、批处理（一次处理一批同类数据）、减少指针（少一次间接跳转）。

这是全书唯一讲「硬件」的一章，也是 DOTS 的理论基础。

Unity 里它长什么样

Unity 的经典写法是 AoS（每个 MonoBehaviour 是一个托管对象，遍历就是跳内存）。三层优化，从便宜到贵：

// 1) 最便宜：缓存组件引用，别在循环里 GetComponent
readonly List<Enemy> enemies = new();
void Awake() { /* 一次性收集 */ }
void Update() { for (int i = 0; i < enemies.Count; i++) enemies[i].Tick(); }

// 2) 中等：数据与行为分离，热数据放数组（SoA）
struct Unit { public Vector3 pos; public float speed; }
Unit[] units = new Unit[10000];

// 3) 最贵但最强：Jobs + Burst + NativeArray
[BurstCompile]
struct MoveJob : IJobParallelFor
{
    public NativeArray<Vector3> pos;
    public float dt;
    public void Execute(int i) => pos[i] += Vector3.forward * dt;
}

Burst 要求代码里没有托管引用（不能用 class、string、List），这是它快的根本原因，也是迁移的主要障碍。

什么时候别用

  • DOTS 学习曲线陡、生态限制多（很多插件不兼容），小项目上它就是纯亏。
  • 普通项目里先做这两件事收益已经很大：去掉每帧 GC Alloc、把 GetComponent 缓存成数组。
  • 别为了「数据局部性」把所有逻辑改成 struct：值类型拷贝、装箱、调试困难会反过来咬你。

10 分钟动手

  1. 写一段循环，对 10000 个对象各调用一次 GetComponent()，计时。
  2. 改成 Awake 里缓存成 Renderer[]，再计时。
  3. 把倍数写下来。这一章的核心不是 DOTS，是「别在热路径里跳内存」。
