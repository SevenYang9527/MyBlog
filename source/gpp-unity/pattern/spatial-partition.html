空间分区

把「两两检查」变成「只查邻居」：先按空间分桶，碰撞与查询的复杂度从 n² 掉到 n。

  • 25 分钟
  • 批次 3 · 按需查
  • Physics 宽相 · OverlapSphere · 网格 / 四叉树

原文在解决什么

一千个对象两两检测 = 五十万次。但绝大多数对象离得很远，根本不可能碰到。空间分区先把世界切成格子（或树），查询时只检查同一格与相邻格。

三种实现：均匀网格（最简单，适合分布均匀）、四叉树 / BVH（自适应，适合稀疏不均）、BSP（静态场景）。

Unity 里它长什么样

物理引擎里已经有一份，而且比你自己写的快得多。你能做的第一件事是别重复造：

// 用物理的宽相，不要自己两两比
readonly Collider[] hits = new Collider[16];

int n = Physics.OverlapSphereNonAlloc(pos, radius, hits, mask);
for (int i = 0; i < n; i++) { /* 处理 */ }

// 注意：OverlapSphere（非 NonAlloc 版）每次都分配数组，高频调用会 GC

真正需要自己写的场景通常是：

  • 2D 大量单位（几千个弹幕、RTS 小兵），物理引擎的 2D 宽相在极端密度下会退化。
  • 非物理的范围查询：视野、光环、建造吸附、迷雾。
  • 静态空间索引：地图分块、NavMesh 分区、LOD 剔除、刷怪点查询。

对应地，Unity 里也有现成的：Physics.OverlapSphere、Physics2D.OverlapCircle、NavMesh 分区、Occlusion Culling 的 Umbra。

什么时候别用

  • 对象少于几百个，两两检测完全够用，n² 在这个量级肉眼不可见。
  • 网格的 cellSize 要接近查询半径：太小=遍历很多格，太大=每格太多对象，两头都退化。
  • 动态对象频繁跨格移动时，维护索引的成本可能超过收益。
  • 先量再写：用 Profiler 确认物理查询或邻近检测是瓶颈。

10 分钟动手

  1. 生成 2000 个点，写双层 for 统计「距离小于 2」的对数，记下耗时。
  2. 换成 4×4 均匀网格，同样统计。
  3. 把两个耗时写进笔记——这就是「什么时候该自己写空间分区」的判据。
