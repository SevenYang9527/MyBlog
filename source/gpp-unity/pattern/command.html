命令模式

把「一个动作」变成对象：能存、能传、能排队、能撤销、能重放。

  • 25 分钟
  • 批次 2 · 架构升级
  • InputAction · 撤销栈 · 录像回放 · AI 指令

原文在解决什么

按键要能重绑、操作要能撤销、对局要能回放、AI 要能发出和玩家一样的指令——这四件事看起来无关，其实都需要同一个东西：动作被具体化成一个可传递的值，而不是「直接调用一个方法」。

Unity 的 Input System 就是命令模式的工业化版本：InputAction 是一个可序列化的动作对象，绑哪个键是资产配置，重绑不改代码。

Unity 里它长什么样

public interface ICommand
{
    void Execute();
    void Undo();
}

public class MoveCommand : ICommand
{
    readonly Transform target;
    readonly Vector3 delta;
    public MoveCommand(Transform t, Vector3 d) { target = t; delta = d; }
    public void Execute() => target.position += delta;
    public void Undo()    => target.position -= delta;
}

// 撤销栈：压栈即执行，出栈即回滚
readonly Stack<ICommand> history = new();
void Do(ICommand c) { c.Execute(); history.Push(c); }
void UndoLast() { if (history.Count > 0) history.Pop().Undo(); }

同一套结构还能干别的：

  • 回放：把每帧命令存进列表，回放时按顺序 Execute。
  • 网络：命令是天然的可序列化单位，比同步 Transform 便宜得多。
  • AI：AI 和玩家都往同一个命令队列里塞指令，规则代码只认命令。

什么时候别用

  • C# 的 delegate / Action 已经覆盖了「传递动作」，不需要为每个方法造一个类。只有当你要撤销、序列化、排队、或需要参数化配置时才建 Command 类。
  • 命令对象会成为垃圾源：高频（每帧）动作别建对象，用结构体或复用池。
  • 撤销栈要能处理「不可逆操作」（如抽卡），这类命令实现 Undo 时抛异常或明确不支持。

10 分钟动手

  1. 给一个「放置建筑 / 摆放道具」功能加 Ctrl+Z 撤销。
  2. 用 ICommand 栈实现，至少两种命令（放置、删除）。
  3. 再试着录 5 秒操作并回放——如果回放正确，说明你的命令已经把「状态变化」和「触发方式」解耦了。
