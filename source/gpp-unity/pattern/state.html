状态模式

把「当前处于什么状态」变成对象，转移逻辑从一堆 if 里搬进状态自己身上。

  • 25 分钟
  • 批次 1 · 引擎主干
  • 手写状态机 · StateMachineBehaviour · Animator

原文在解决什么

角色的行为通常写成 if (state == Jumping) ... else if (state == Ducking) ...，再加输入、再加动画，很快就变成嵌套地狱。状态模式把每个状态提成一个对象，只实现「进入 / 每帧 / 退出」，状态之间的转移由状态自己（或一张表）决定。

作者还给了两个进阶：层次状态机（OnGround 下含 Idle/Run，共用「跳」的转移）和并发状态机（移动与武器各一套，互不干扰）。

Unity 里它长什么样

Animator 本身就是状态机，但别把游戏逻辑塞进 Animator：它的转移条件表达能力弱、调试只能看连线、逻辑散落在资产里无法 diff。逻辑用 C#，Animator 只负责表现。

public interface IState
{
    void Enter();
    void Tick(float dt);
    void Exit();
}

public class StateMachine
{
    IState current;
    public void Change(IState next)
    {
        current?.Exit();
        current = next;
        current?.Enter();
    }
    public void Tick(float dt) => current?.Tick(dt);
}

// 用法：idle / run / jump / hurt 各一个类
fsm.Change(new JumpState(rb, jumpForce));

状态少于 3 个时，enum + switch 反而更省事——别为了模式而模式。超过 5 个、或开始出现「同一段转移代码抄三遍」，就换状态类。

什么时候别用

  • 状态类会爆炸：Idle/Run/Jump/Fall/Hurt/Dead/Attack/... 十个类之后，考虑用转移表（数据驱动）代替「状态自己决定下一步」。
  • 别为「一次性动作」建状态类，用协程或 Timeline。
  • 状态机不适合表达「可并行、可打断、有优先级」的行为——那是行为树或 GOAP 的领域。

10 分钟动手

  1. 找一个用 bool isJumping / isHurt / isDead 三件套的角色脚本。
  2. 改成 4 个状态类 + 一台状态机。
  3. 新增一个「落地硬直」状态，数一下你改了几个文件——如果只加了一个类、改了两处转移，说明拆分是对的。
