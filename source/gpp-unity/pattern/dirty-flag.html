脏标识

算一次很贵、但数据很少变——那就别每帧算，用一个小布尔记住「该重算了」。

  • 20 分钟
  • 批次 3 · 按需查
  • 属性缓存 · UI 刷新节流 · Animator 参数

原文在解决什么

有些计算很贵（排序、布局、合并网格、算属性总加成），但输入很少变。做法：数据改动时把一个 dirty 标记置 true，真正需要结果时才重算，算完清标记。

它把「每次读都算」变成「每次写后只算一次」，代价是一个标记和一段容易漏更新的代码。

Unity 里它长什么样

引擎内部到处是脏标记：Canvas 的 SetVerticesDirty / SetLayoutDirty、Animator 的参数哈希、Transform.hasChanged。

自己写一个最小版本，最常见的是「装备加成后的属性」：

public class StatBlock
{
    int baseAtk = 5;
    readonly List<int> bonuses = new();

    int cached;
    bool dirty = true;

    public void AddBonus(int v) { bonuses.Add(v); dirty = true; }
    public void ClearBonuses()  { bonuses.Clear(); dirty = true; }

    public int TotalAtk
    {
        get
        {
            if (dirty)
            {
                cached = baseAtk;
                foreach (var b in bonuses) cached += b;
                dirty = false;
            }
            return cached;
        }
    }
}

UI 里更常见的用法是节流：数据变了只置标记，在 LateUpdate 里统一刷新一次，而不是每次赋值都 text = ...（Text 重建网格很贵）。

什么时候别用

  • 读多写少才有收益。写多读少时，标记的开销比直接算还大。
  • 多级依赖的脏传播是复杂度来源：A 依赖 B 依赖 C，C 变了要能把 A 也标脏。链一长就容易漏更新，出现「数值不刷新」的诡异 bug。
  • 别对「每帧都在变的量」用脏标记，那是纯开销。

10 分钟动手

  1. 找一个每帧刷新的 UI Text（比如血量、金币、倒计时）。
  2. 改成「赋值时只置脏 + LateUpdate 里检查脏再刷新」。
  3. 在 Profiler 里比较 Canvas.SendWillRenderCanvases 的耗时。
