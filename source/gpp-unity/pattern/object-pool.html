对象池

池化省下来的不是创建时间，是 GC：不再反复分配，垃圾回收就不会在战斗中途卡一下。

  • 20 分钟
  • 批次 3 · 按需查
  • UnityEngine.Pool · ListPool / HashSetPool · 自定义池

原文在解决什么

频繁 new / delete（或 Instantiate / Destroy）的代价有三层：分配本身、随之而来的垃圾回收、以及内存碎片导致的缓存失效。对象池让对象「回收再发」，复用同一批内存。

关键认识：收益主要在避免 GC 尖峰，而不是省掉那点构造时间。所以判断要不要池化，看 Profiler 的 GC Alloc，别凭感觉。

Unity 里它长什么样

Unity 内置了泛型池（UnityEngine.Pool，2021.1+）：

using UnityEngine.Pool;

ObjectPool<Bullet> pool;

void Awake()
{
    pool = new ObjectPool<Bullet>(
        createFunc:      () => Instantiate(bulletPrefab).GetComponent<Bullet>(),
        actionOnGet:     b  => b.gameObject.SetActive(true),
        actionOnRelease: b  => b.gameObject.SetActive(false),
        actionOnDestroy: b  => Destroy(b.gameObject),
        collectionCheck: true,      // 编辑器下抓「重复 Release」
        defaultCapacity: 32,
        maxSize:         128);
}

void Fire(Vector3 dir)
{
    var b = pool.Get();
    b.Launch(dir);
    // 子弹超时或命中后：pool.Release(b);
}

还有 ListPool / HashSetPool / StringBuilderPool，用来干掉每帧临时集合的分配，收益往往比子弹池更大。

什么时候别用

  • 状态残留是最常见的 bug：复用的对象带着上一轮的血量、粒子、协程。OnRelease 里必须彻底重置。
  • 池化会掩盖真实的分配问题：先在 Profiler 里确认 GC Alloc 是瓶颈，再上池。
  • SetActive 也有成本（层级重建、OnEnable 调用），超高频时改用「移出屏幕 / 关闭 Renderer」。
  • 池化 GameObject 会让层级里塞满隐藏对象，记得放在专用父节点下。

10 分钟动手

  1. 打开 Profiler → CPU → Hierarchy，勾 GC Alloc 列。
  2. 让角色连续射击 10 秒，记下每帧的 GC Alloc。
  3. 加子弹池和 ListPool，再测一次。数字变化就是这一章的分数。
