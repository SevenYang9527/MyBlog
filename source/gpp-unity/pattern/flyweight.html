享元

一千棵树只需要一份「树的样子」，各自只存位置和大小。共享的部分越多，内存越省。

  • 20 分钟
  • 批次 3 · 按需查
  • 共享 Mesh / Material · GPU Instancing · SO 共享数据

原文在解决什么

场景里成千上万个相似对象，如果每个都带一份完整的网格、贴图、动画数据，内存立刻爆掉。享元把状态分成两类：

  • 内禀状态：所有实例共享、永不改变（网格、材质、贴图、动画曲线）。
  • 外禀状态：每个实例独有（位置、旋转、血量、颜色）。

共享内禀，只存外禀。作者还提醒：这不是免费午餐——一旦共享数据被改，所有实例一起变。

Unity 里它长什么样

Unity 的资源系统天生就是享元：一个 Material 资产被一千个 Renderer 引用，内存里只有一份。

// 灾难写法：每次访问 .material 都会实例化一份材质（克隆）
renderer.material.color = Color.red;

// 正确写法一：确实要改，用 sharedMaterial 并接受「全体一起变」
renderer.sharedMaterial.color = Color.red;

// 正确写法二：只想改这一个实例，用 MaterialPropertyBlock（不产生材质实例）
static readonly int ColorId = Shader.PropertyToID("_Color");
var mpb = new MaterialPropertyBlock();
renderer.GetPropertyBlock(mpb);
mpb.SetColor(ColorId, tint);
renderer.SetPropertyBlock(mpb);

其它常见落点：GPU Instancing（同网格同材质一次画完）、Terrain 的树与草、Prefab 变体、ScriptableObject 共享配置（见类型对象）、Sprite Atlas（合图减少切换）。

什么时候别用

  • 共享 = 「一改全变」。如果每个实例都要独立外观，它就是错的方案。
  • 每实例一个材质实例（renderer.material）是 Unity 项目里最常见的内存与 Draw Call 杀手。
  • 别共享「会变的运行时数据」，那会导致一个对象受伤、全场一起掉血。

10 分钟动手

  1. 全局搜 .material（不是 .sharedMaterial），看有多少处。
  2. 挑一处改成 MaterialPropertyBlock。
  3. 在 Frame Debugger 里看 Draw Call 与 SetPass 的变化。
