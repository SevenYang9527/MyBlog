类型对象

把「类型」从代码里搬进数据：一个类型就是一个对象，策划改配置不用重新编译。

  • 25 分钟
  • 批次 2 · 架构升级
  • ScriptableObject · CreateAssetMenu · Addressables

原文在解决什么

当「类型」本身就是内容（怪物种类、武器、法术），用继承会让类数量随内容线性增长，而且策划每次调数值都要等程序员编译。类型对象把「类型」变成一个运行期对象：实例持有指向类型的引用，类型的属性存在这个对象里。

对 Unity 来说，这一章几乎是全书的最高性价比——它直接对应 ScriptableObject。

Unity 里它长什么样

[CreateAssetMenu(menuName = "GPP/Enemy Type")]
public class EnemyType : ScriptableObject
{
    public string displayName;
    public Sprite icon;
    public GameObject prefab;
    public int maxHp = 10;
    public float moveSpeed = 2f;
    [Range(0f, 1f)] public float armor;
}

public class Enemy : MonoBehaviour
{
    [SerializeField] EnemyType type;

    void Awake()
    {
        var h = gameObject.AddComponent<Health>();
        h.Init(type.maxHp, type.armor);
        GetComponent<Mover>().speed = type.moveSpeed;
    }
}

然后在 Project 里 右键 → Create → GPP → Enemy Type，拖进预制体。策划加第 4 种敌人 = 复制一个资产改数值，零代码。

三个必须知道的坑：

  1. ScriptableObject 是资产，运行时写它会污染磁盘文件（编辑器下尤其明显）。要运行时状态就 Instantiate(so) 一份副本，或只存只读配置。
  2. SO 之间互相引用会让 Addressables 把依赖图全量打进去。大项目用 AssetReference 延迟加载。
  3. SO 里放行为（虚方法）很香，但会让「数据」和「代码」耦合进资产，重构时资产失效。先只放数据，行为用 Strategy 接口注入。

什么时候别用

  • 只有 2-3 个固定的、永不变化的类型，用 enum 或普通类字段更简单。
  • 需要「每帧变化的数值」不要放 SO，那是运行时状态。
  • 别把 SO 当单例用（见单例那章的「SO 服务」），只读配置才安全。

10 分钟动手

  1. 找出项目里硬编码的 3 种敌人参数（写在 switch 或 if 里的那些）。
  2. 抽成 3 个 SO 资产，预制体上换成引用。
  3. 试着「不加一行代码」加出第 4 种——如果做到了，这一章你就真的学会了。
