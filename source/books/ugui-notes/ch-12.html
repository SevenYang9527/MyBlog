字体：UGUI 里最容易被低估的成本

讲义第 28 页把字体问题拆成七条：字体图集的重建机制、后备字体机制、Text 的网格重建、提前生成动态字体、使用美术数字、谨慎使用 Best Fit、减少长文本变动并慎用 UI/Effect。这些内容在 2018 年是很实用的经验；今天看，大部分仍然成立，但有两处需要修正，而且必须把 TextMeshPro 拉进来一起讲。

Legacy Text 与 TextMeshPro

UGUI 自带的 UnityEngine.UI.Text 现在通常被称为 Legacy Text。它使用动态字体：需要哪个字，就把哪个字的光栅化结果放进字体图集；不同字号通常需要不同的字形位图。TextMeshPro（TMP）使用 Signed Distance Field（SDF）图集：一个字形可以服务多个字号和缩放，描边/阴影主要通过材质和 Shader 实现，而不是复制顶点。

维度Legacy TextTextMeshPro
图集动态字体图集，按字号光栅化；字号越多，图集压力越大。SDF 图集，一个字形可服务多字号；仍有图集大小和 fallback 管理。
描边/阴影Shadow / Outline 复制顶点：Shadow 约 2 倍，Outline 约 5 倍。通常通过材质/Shader 实现，不复制顶点；但仍有额外采样/绘制成本。
清晰度依赖字号和图集分辨率；大字号需要单独生成。缩放更平滑；极小字号/复杂字形仍需调采样和 padding。
功能基础排版、富文本；复杂排版能力有限。更丰富的排版、字符间距、行距、表情/精灵、超链接等。
适用老项目、少量简单文本、迁移成本敏感新项目默认选择；大量文本、多语言、需要高质量描边/阴影

讲义没有提 TMP，这是时代限制。今天做新项目，除非有明确的迁移成本或兼容性原因，否则应优先 TMP；但 TMP 不是“零成本”：Font Asset、Material Preset、Fallback、动态图集、多语言字符集都需要设计。

动态字体图集的重建

Legacy Text 的动态字体图集不是一次性生成的。当文本里出现新字符，Unity 会把它加入图集；图集满了，就会触发重建。重建的目标是容纳当前需要显示的字符；如果空间不够，图集可能会扩容。具体重建尺寸和时机属于实现细节，不同版本可能不同，不要写代码去依赖“它一定按原尺寸重建”。

需要稳定的地方是：重建后，旧字形的 UV 可能失效，所有使用该字体的 Text 都需要重新生成网格。UGUI 内部通过 FontUpdateTracker 和 Font.textureRebuilt 处理这件事；如果你自己用 Font.RequestCharactersInTexture 生成自定义网格，就必须监听 Font.textureRebuilt，在重建后重新请求字符、重建网格。

using UnityEngine;

public class FontPrewarm : MonoBehaviour
{
    public Font font;
    public int fontSize = 28;

    void OnEnable()
    {
        Font.textureRebuilt += OnFontTextureRebuilt;
        Request();
    }

    void OnDisable()
    {
        Font.textureRebuilt -= OnFontTextureRebuilt;
    }

    void Request()
    {
        // 预先把常用字符放进图集；仅对动态字体有意义
        font.RequestCharactersInTexture("0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ", fontSize, FontStyle.Normal);
    }

    void OnFontTextureRebuilt(Font rebuiltFont)
    {
        if (rebuiltFont != font) return;
        Request();
        // 如果你有自定义网格，这里还要重新生成 UV/顶点
    }
}

Font.RequestCharactersInTexture 的文档特别提醒：图集重建后，只保留“上一帧使用过”的字符。所以即使字符当前已经在图集里，也建议在需要时重新请求，避免它在重建时被清掉。这个 API 主要面向自定义文本渲染；普通 Text 组件会自己处理。

后备字体：不是简单的 Arial.ttf

讲义说“后备字体取自系统自带的 Arial.ttf，在发布的游戏安装包里该字库是不存在的”。这句话过于绝对，而且容易误导跨平台项目。更准确的机制是：

  • Unity 的默认字体资源在文档里被描述为使用 Arial 的动态字体；如果系统没有 Arial，会回退到 Unity 自带的 Liberation Sans。
  • 字体资源可以配置 Font Names 后备字体列表；当主字体缺少某个字形时，Unity 会按列表查找项目内或系统上可用的字体。
  • 如果列表里的字体都不可用，Unity 还会回退到一个硬编码的全局后备字体列表，其中包含当前平台常见的国际字体。
  • WebGL、部分主机平台没有可访问的 OS 字体；这些平台不能依赖 Arial 或系统字体，字体数据必须随项目提供，后备字体也要在项目里配置。

所以“安装包里没有 Arial”在某些平台可能是事实，但不是通用结论；更重要的是“不要假设目标平台一定有某个系统字体”。多语言项目应该显式配置 Font Asset / Fallback，并在目标平台上验证生僻字、粗体、斜体是否正常。

考据结论：“后备字体来自系统 Arial.ttf、安装包里不存在”不准确。默认字体与 Arial 有关，但缺失时会回退到 Liberation Sans 或系统/全局 fallback；WebGL/主机不能依赖 OS 字体。跨平台项目必须自带字体数据并配置 fallback。

Text 的网格重建

讲义说“Text 组件被重新启用的时候，会重建 Text 的网格。如果含有大量文字，会造成严重的 CPU 开销”。这是对的。除此之外，以下情况也会触发 Text 重建：

  • text 字符串变化：SetVerticesDirty + SetLayoutDirty。
  • 字体、字号、样式、行距、对齐、换行模式变化：通常都会弄脏顶点和布局。
  • 字体图集重建：FontTextureChanged 会触发 SetAllDirty 或直接 UpdateGeometry。
  • RectTransform 尺寸变化：如果文本参与布局或换行，需要重新排版。
  • 组件启用：OnEnable 会 SetAllDirty。

所以“长文本每帧变”是很贵的：每次都要重新排版、生成顶点、可能触发布局。能不做就不做；必须做时，考虑拆分文本、只更新变化的部分、用 TMP 的 SetText 重载减少临时字符串。

Best Fit：方便但昂贵

讲义说“Best Fit 虽然可以动态调整字体大小以适应 UI 布局，但代价很高；Unity 会为用到的所有字号生成图元保存在图集里，增加生成时间，也让字体图集变大”。这个方向是对的：Best Fit 需要在最小和最大字号之间尝试，找到能放下的字号；这会增加排版次数，也可能让图集里出现多个字号的光栅化结果。

更稳的做法：

  • 固定字号，用布局/换行/省略号处理溢出，而不是让字号自动缩。
  • 静态文本可以在 Editor 里用 Best Fit 找到合适字号，然后关掉 Best Fit，写死字号。
  • 必须动态适配时，限制 Best Fit 的 min/max 范围，避免跨度太大。
  • TMP 的 Auto Size 同样会多次排版；TMP 文档也建议对频繁变化的动态文本避免 Auto Size。

UI/Effect 的顶点成本

讲义说“描边和阴影效果都会增大四倍的顶点数”。这句话是错的，而且错得很典型。UGUI 的 Shadow 和 Outline 都是 BaseMeshEffect，通过复制顶点实现：

  • Shadow：复制一份顶点并偏移，最终约为原来的 2 倍。
  • Outline：在四个方向各复制一份，最终约为原来的 5 倍（原始 1 份 + 4 份）。
  • 如果同时挂 Shadow 和 Outline，成本会继续叠加。

因此，长文本 + Outline 是非常昂贵的组合。更好的方案：用 TMP 的材质描边/阴影；把描边烘焙进字体图集或图片；用 Shader 在片元阶段做描边；或者只在标题等少量文本上使用 Effect。

用美术数字代替 Text

讲义建议“游戏的分数可以用美术数字（精灵图片）来代替 Text”。这在很多游戏里有效，尤其是数字变化频繁、字体风格强的界面。但它不是免费的：每个数字是一张图/一个 Image，可能增加 DrawCall 和 Overdraw；如果数字图不在同一图集，还会断批。适合“高频变化 + 固定样式 + 数量不大”的场景。现代替代方案是 TMP 的 Sprite Asset / 数字图集，或者用 Shader 做数字滚动。

一段 TMP 的实用写法

using TMPro;
using UnityEngine;

public class ScoreView : MonoBehaviour
{
    public TMP_Text label;

    int lastScore = -1;

    public void SetScore(int score)
    {
        if (score == lastScore) return;
        lastScore = score;

        // SetText 的重载可以避免中间字符串分配
        label.SetText("Score: {0}", score);
    }
}

如果是打字机效果，不要每帧重新拼字符串，可以用 TMP_Text.maxVisibleCharacters 控制显示范围；如果需要频繁改文本，注意 SetText 的重载和 ForceMeshUpdate 的调用时机。

考据结论：讲义第 28 页的大部分字体策略成立；需要修正“后备字体是 Arial.ttf”和“Shadow/Outline 都增大 4 倍顶点”两处。新项目应把 TMP 纳入字体方案；长文本、Best Fit、Outline/Shadow 仍然是重点监控对象。
