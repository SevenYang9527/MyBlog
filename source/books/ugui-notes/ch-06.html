把 RectTransform 算清楚：三个公式就够了

讲义第 13 到 18 页问了一连串问题：rect 的 x、y 是什么？anchoredPosition 在两个形态下分别表示什么？sizeDelta 在两个形态下分别表示什么？在锚框形态下怎么读、怎么设 UI 的尺寸？这些问题其实可以用三个公式回答。把这三个公式记住，比背 Inspector 上的字段有用得多。

公式一：实际尺寸

size = parentSize * (anchorMax - anchorMin) + sizeDelta

当 anchorMin == anchorMax 时，括号里是 0，size = sizeDelta；当锚点分开时，sizeDelta 是“实际尺寸和锚框尺寸的差”，可以是负数。比如四边拉伸、左右各留 20 像素时，sizeDelta.x = -40。

公式二：锚点参考点

anchorRef = parentRect.min + parentRect.size * Lerp(anchorMin, anchorMax, pivot)
pivotPos  = anchorRef + anchoredPosition

anchoredPosition 是轴心相对锚点参考点的偏移，不是相对父物体中心，也不是相对左下角。锚点重合时，anchorRef 就是那个锚点；锚点分开时，它是锚框里按 pivot 比例插值出来的点。

公式三：局部矩形

rect.size = size
rect.min  = -Vector2.Scale(size, pivot)
rect.max  = rect.min + size

RectTransform.rect 是“以轴心为原点”的局部矩形。轴心在中心时，范围是 (-w/2, -h/2, w, h)；轴心在左下角时，范围是 (0, 0, w, h)。所以讲义说“rect 的 x、y 是轴心点到矩形框左下角的向量值”是对的，只不过这个向量通常指向负方向。

在锚框形态下读尺寸、设尺寸

讲义把这两个问题单独列出来，因为它们是实际开发里最容易踩坑的地方。答案如下：

目标推荐写法说明
读实际尺寸rectTransform.rect.size不要读 sizeDelta，除非你确认锚点重合。
设实际尺寸（保持当前锚点）SetSizeWithCurrentAnchors(Axis.Horizontal, w) 和 Axis.Vertical内部会按锚框尺寸反算 sizeDelta，最适合锚框形态。
设四边边距offsetMin / offsetMaxLeft/Bottom 对应 offsetMin，Right/Top 对应 offsetMax；适合做 padding。
设 sizeDelta先算锚框尺寸，再写差值例如 sizeDelta = desiredSize - anchorRectSize；不直观，容易错。

SetSizeWithCurrentAnchors 的源码逻辑可以写成：

// 以 Horizontal 为例
sizeDelta.x = size - parentRect.width * (anchorMax.x - anchorMin.x);

这就是为什么锚点分开时不能直接写 sizeDelta = new Vector2(w, h)：它会被解释成“比锚框大多少/小多少”，而不是“最终宽度是多少”。

三个具体例子

例 1：锚点形态，居中。父矩形 1000 × 500，锚点 (0.5, 0.5)，轴心 (0.5, 0.5)，sizeDelta = (200, 100)，anchoredPosition = (0, 0)。

  • 实际尺寸：200 × 100。
  • 锚点参考点：(500, 250)。
  • rect：(-100, -50, 200, 100)。

例 2：四边拉伸，左右各 20、上下各 10。父矩形 1000 × 500，anchorMin = (0, 0)，anchorMax = (1, 1)，pivot = (0.5, 0.5)，offsetMin = (20, 10)，offsetMax = (-20, -10)。

  • 实际尺寸：960 × 480。
  • sizeDelta = (-40, -20)。
  • 轴心居中，anchoredPosition = (0, 0)（因为上下左右边距对称）。

例 3：水平拉伸，高度固定 100。父矩形 1000 × 500，anchorMin = (0, 0.5)，anchorMax = (1, 0.5)，pivot = (0.5, 0.5)，sizeDelta = (-40, 100)。

  • 实际宽度：960。
  • 实际高度：100（锚框高度为 0，sizeDelta.y 就是高度）。
  • anchoredPosition = (0, 0) 表示轴心在锚点线上；如果要垂直偏移，改 anchoredPosition.y。

一段“按锚点设尺寸”的工具代码

using UnityEngine;

public static class RectTransformUtil
{
    public static void SetSize(RectTransform rt, float width, float height)
    {
        rt.SetSizeWithCurrentAnchors(RectTransform.Axis.Horizontal, width);
        rt.SetSizeWithCurrentAnchors(RectTransform.Axis.Vertical, height);
    }

    public static void SetPadding(RectTransform rt, float left, float bottom, float right, float top)
    {
        rt.offsetMin = new Vector2(left, bottom);
        rt.offsetMax = new Vector2(-right, -top);
    }

    public static void Print(RectTransform rt)
    {
        var p = rt.parent as RectTransform;
        Debug.Log($"size={rt.rect.size}, sizeDelta={rt.sizeDelta}, " +
                  $"anchoredPos={rt.anchoredPosition}, " +
                  $"anchors=({rt.anchorMin},{rt.anchorMax}), pivot={rt.pivot}, " +
                  $"parent={(p ? p.rect.size.ToString() : "null")}");
    }
}

注意：SetPadding 只在锚点分开时有意义；锚点重合时 offsetMin/Max 仍然会改 sizeDelta 和位置，但不是“四边 padding”的语义。

考据结论：讲义对 rect、anchoredPosition、sizeDelta 的解释基本正确；需要补充“锚点参考点”和三个公式。讲义问的“锚框形态下怎么读/怎么设尺寸”，答案是：读 rect.size，设 SetSizeWithCurrentAnchors 或 offsetMin/Max，不要直接拿 sizeDelta 当尺寸。

布局组件会接管这些值

如果父物体上有 HorizontalLayoutGroup、VerticalLayoutGroup、GridLayoutGroup 或 ContentSizeFitter，它们会在布局阶段写子物体的 anchoredPosition、sizeDelta，甚至 anchorMin/Max。这时你在 Update 里手动设置的值可能每帧被覆盖。

判断方法：运行时看 RectTransform.drivenByObject 是否非空，或者看 Inspector 里被驱动的字段是否变灰。被布局驱动时，应该改布局组或 LayoutElement 的参数，而不是硬改 RectTransform。

var driven = rectTransform.drivenByObject;
if (driven != null)
    Debug.Log($"RectTransform 被 {driven.name} 驱动");

这也是为什么“在代码里设了尺寸但没生效”经常不是 RectTransform 的问题，而是布局组在下一帧把它改回去了。
