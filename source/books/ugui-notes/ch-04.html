04 · 适配：Canvas Scaler 的三种模式与两种匹配

适配不是“把 UI 拉大”，而是选一套缩放规则

讲义第 6 页把 Canvas Scaler 拆成两个维度：UI Scale Mode（按什么单位描述 UI）和 Screen Match Mode（宽高比不一致时怎么缩放画布）。这个拆法是对的，但讲义只给了结论，没有给公式和适用条件。本章把这两层补齐。

三种 UI Scale Mode

模式行为适合不适合
Constant Pixel SizeUI 的位置和尺寸按屏幕像素描述；可以通过 Scale Factor 再整体乘一个系数。像素风、需要严格按像素对齐的界面、固定分辨率的小工具手机/多分辨率项目；不同 DPI 下 UI 会显得过大或过小。
Scale With Screen Size以一套 Reference Resolution 为设计基准，按屏幕分辨率整体缩放画布。大多数移动端、PC、主机 UI需要物理尺寸一致的界面；需要极端的宽高比适配时，要配合锚点和安全区。
Constant Physical Size按物理单位（厘米、毫米、英寸、点、派卡）描述 UI；依赖设备上报的 DPI。需要“按钮大约 1 厘米高”的跨设备界面DPI 上报不可靠的设备；游戏 UI 很少用。

World Space Canvas 不走上面三种模式，而是用 Dynamic Pixels Per Unit 控制动态生成位图（例如 Text）的像素密度。这个值太低，文字会糊；太高，字体图集和内存会涨。

Scale With Screen Size 的三种匹配

当屏幕宽高比和参考分辨率不一致时，Canvas Scaler 需要决定“以宽为准、以高为准，还是折中”。这就是 Screen Match Mode。讲义列了三种，但把 Match Width or Height 说成“按照宽度或高度来缩放”，容易让人以为是线性插值。实际实现是在对数空间做加权平均。

// 以 CanvasScaler 源码为准（省略屏幕尺寸获取）
float logWidth  = Mathf.Log(screenW / refW, 2);
float logHeight = Mathf.Log(screenH / refH, 2);
float logAvg    = Mathf.Lerp(logWidth, logHeight, match);
float scale     = Mathf.Pow(2, logAvg);

其中 match = 0 时完全按宽度，match = 1 时完全按高度，match = 0.5 时在 log 空间取中点。为什么不用普通平均？因为“宽度放大 2 倍”和“高度缩小 2 倍”在普通空间平均会得到 1.25，而在对数空间平均正好回到 1，视觉上更中性。

Screen Match Mode源码公式直观效果代价
Match Width or Height2^lerp(log2(screenW/refW), log2(screenH/refH), match)在宽高之间折中；match 越靠 0 越按宽度，越靠 1 越按高度。宽高比差异大时，总有一边会多出或少掉空间，需要用锚点/安全区处理。
Expandmin(screenW/refW, screenH/refH)画布只会变大，不会小于参考分辨率；参考分辨率里的内容能全部显示。屏幕上会出现参考分辨率之外的区域；背景/边框要能延展。
Shrinkmax(screenW/refW, screenH/refH)画布只会变小，不会大于参考分辨率；画面填满，不留黑边。参考分辨率边缘的内容可能被裁掉；重要 UI 要放在安全区内。

一个实战选型

移动端横屏项目常见的一套配置是：

  • UI Scale Mode：Scale With Screen Size。
  • Reference Resolution：1920 × 1080（按你的设计稿来，不必迷信这个数）。
  • Screen Match Mode：Match Width or Height，Match = 0.5 作为起点。
  • 重要 UI 用锚点贴边，并加安全区；不要在代码里按屏幕宽度硬编码位置。
  • 背景图允许超出屏幕，或者用 Expand 保证设计内容不丢；要让画面填满时再评估 Shrink。

竖屏项目通常把参考分辨率设成 1080 × 1920，Match 更偏向高度；但“偏向高度”不是必须 1.0，仍然要根据刘海、圆角和虚拟键盘的实际测试来调。

考据结论：讲义对三种 Scale Mode 和三种 Screen Match Mode 的描述大体正确；“Match Width or Height 按宽度或高度缩放”需要补充为“对数空间加权”。Expand / Shrink 的“保证全部显示 / 可能裁掉边缘”是准确的，但都要配合锚点和安全区。

安全区：Canvas Scaler 管不到的地方

Canvas Scaler 只负责整体缩放，不负责避开刘海、挖孔和圆角。安全区要用 Screen.safeArea 自己处理。一个常见的做法是给根面板加一个“安全区适配”组件，把 Canvas 的 Screen.safeArea 转换成 anchorMin/anchorMax：

using UnityEngine;

[RequireComponent(typeof(RectTransform))]
public class SafeAreaFitter : MonoBehaviour
{
    RectTransform rect;
    Rect lastSafeArea;

    void Awake()
    {
        rect = GetComponent<RectTransform>();
        Apply();
    }

    void Update()
    {
        if (Screen.safeArea != lastSafeArea)
            Apply();
    }

    void Apply()
    {
        lastSafeArea = Screen.safeArea;
        var min = lastSafeArea.position;
        var max = lastSafeArea.position + lastSafeArea.size;
        min.x /= Screen.width;
        min.y /= Screen.height;
        max.x /= Screen.width;
        max.y /= Screen.height;
        rect.anchorMin = min;
        rect.anchorMax = max;
        rect.offsetMin = Vector2.zero;
        rect.offsetMax = Vector2.zero;
    }
}

注意：这个组件只适合挂在“需要避开安全区”的根节点上；不要给每个子元素都挂一遍，否则布局会互相打架。

代码里改 Canvas Scaler 的注意事项

CanvasScaler 只对根 Canvas 生效；源码里 Handle() 会检查 m_Canvas.isRootCanvas，嵌套 Canvas 上的 CanvasScaler 不会单独计算。运行时修改 referenceResolution 或 matchWidthOrHeight 后，通常要等下一次 Canvas.preWillRenderCanvases 才生效；如果必须立刻拿到新尺寸，可以调用 Canvas.ForceUpdateCanvases()，但不要每帧调用。

var scaler = canvas.GetComponent<CanvasScaler>();
scaler.uiScaleMode = CanvasScaler.ScaleMode.ScaleWithScreenSize;
scaler.referenceResolution = new Vector2(1920, 1080);
scaler.screenMatchMode = CanvasScaler.ScreenMatchMode.MatchWidthOrHeight;
scaler.matchWidthOrHeight = 0.5f;

最后提醒一句：Canvas Scaler 解决的是“整体缩放”，锚点解决的是“相对父物体的位置和尺寸”，布局组解决的是“子元素的排列”。这三件事不要混成一个问题。
