勘误总表：哪些话可以继续信

这一章把讲义里的主要结论按页码汇总，给出判定和依据。判定分五档：

  • 真：在当前版本下仍然成立，可以直接使用。
  • 大体真：方向正确，但需要补充条件或版本差异。
  • 过时：在讲义写作时可能成立，今天已经需要改写。
  • 不准确 / 假：表述会误导优化方向，或与源码/文档冲突。
  • 经验：属于项目经验或团队规范，无法用“真/假”判断，只能看适用条件。

同义句会合并；讲义里的项目案例（如《龙与少女》）不逐条判定，只在涉及通用机制时引用。

一、UI 系统与 Canvas（第 3-5 页）

讲义说法判定依据 / 修正
IMGUI 是 Unity 自带的古老 UI 系统真立即模式，主要用于 Editor 和调试；不适合正式运行时 UI。
NGUI 是最流行的第三方 UI 插件过时NGUI 在 Unity 4/5 时代流行；今天新项目很少首选，不能作为选型依据。
FairyGUI 是跨平台 UI 系统，商业案例小游戏居多大体真 / 经验跨平台和编辑器工作流是事实；“小游戏居多”是经验观察，无法量化。
UGUI 是官方版本真Unity UI，包名 com.unity.ugui，仍然受支持。
UI Element 是最新 UI 系统（Unity 2019 版）过时 / 不准确原名 UIElements，2019.1 主要服务 Editor；运行时 UI 自 2021.2 起可用，现名 UI Toolkit。
UGUI 开源地址是 Bitbucket过时现在源码在 GitHub Unity-Technologies/uGUI；排查时优先看项目 Library/PackageCache。
选择 UGUI 因为团队最擅长经验合理且重要，但不是技术事实；团队熟练度往往比纸面性能差异更大。
选择 UGUI 因为官方支持 / 流行趋势大体真官方支持是事实；“流行”是时效判断，且 UI Toolkit 也在增长。
UGUI 支持多线程（UI 重建）不准确Canvas 批次计算/几何 Job 可多线程；C# 侧 Layout / Graphic Rebuild 仍在主线程。
所有 UI 控件都要作为 Canvas 子对象才能渲染真可见 Graphic 需要 Canvas 祖先；每个 Graphic 还有 CanvasRenderer。
按排列顺序渲染，上方先、下方后；嵌套先父后子真按 Hierarchy 深度优先；前面的在底层，后面的盖在上面。不是屏幕空间的“上方”。
Overlay 不需要 UI 相机，覆盖整个画面，永远在最上面大体真相对于场景物体成立；多个 Overlay Canvas 仍按 Sorting Layer / Order 排序。
Screen Space - Camera 需要 UI 相机，画布放在相机前真由指定相机渲染；相机参数会影响 UI；场景物体可能挡在 UI 前。
World Space 把画布当普通 3D 对象，可自由移动旋转真需要 Event Camera；像素密度用 Canvas Scaler 的 Dynamic Pixels Per Unit 控制。

二、适配与 RectTransform（第 6-18 页）

讲义说法判定依据 / 修正
Scale With Screen Size 按标准分辨率设置 UI真Reference Resolution 是设计基准；屏幕分辨率不同会整体缩放。
Constant Pixel Size 按屏幕像素设置 UI真可用 Scale Factor 再乘系数；多 DPI 项目要谨慎。
Constant Physical Size 可用厘米/英寸等物理单位真依赖设备上报 DPI；Screen.dpi 为 0 时用 Fallback DPI。
Match Width or Height 按宽度或高度缩放画布大体真实际在 log 空间做加权平均：2^lerp(log2(w/rw), log2(h/rh), match)。
Expand 保证标准分辨率下的内容全部显示真scale = min(w/rw, h/rh)；画布不会小于参考分辨率，可能露出额外区域。
Shrink 不留黑边但可能显示不全真scale = max(w/rw, h/rh)；画布不会大于参考分辨率，边缘可能被裁。
RectTransform 包含锚点、轴心、坐标、旋转、缩放真此外还有 sizeDelta、offsetMin/Max、rect 等派生属性。
Blueprint 模式编辑未旋转/缩放的矩形真忽略旋转和缩放，并支持吸附。
Raw Edit 模式 pivot 保持相对位置，UI 跟随 pivot 移动大体真更准确：关闭“改 pivot/anchor 时自动反向调整位置和尺寸以保持矩形不动”的行为。
轴心是旋转和缩放的基准点真也是 rect 局部坐标的原点。
锚框范围不能超过父矩形不准确编辑器拖动时默认限制；按住快捷键/输入数值/代码可以超出 0~1。这是约定，不是引擎限制。
锚点形态：大小不随父变，位置跟随真anchorMin == anchorMax；sizeDelta == size。
锚框形态：大小随父变真anchorMin != anchorMax；实际尺寸 = 锚框尺寸 + sizeDelta。
Left/Bottom/Right/Top 是相对锚框的边距真对应 offsetMin / offsetMax；适合四边拉伸。
Anchors 的 Min/Max 是 0~1 的归一化值大体真常规 UI 在 0~1；代码和编辑器输入可以超出，用于特殊效果。
rect 的 x、y 是轴心到左下角的向量真rect.min = -pivot * size；通常为负值。
anchoredPosition 在锚点形态下是锚点到轴心真严格说是“轴心相对锚点参考点”的偏移。
anchoredPosition 在锚框形态下是锚框某点到轴心真那个“某点”是 anchor reference point：Lerp(anchorMin, anchorMax, pivot) 对应的点。
sizeDelta 在锚点形态下是 size，在锚框形态下是尺寸差真size = parentSize * (anchorMax - anchorMin) + sizeDelta。
锚框形态下读/设尺寸：用 sizeDelta 即可不准确读用 rect.size；设用 SetSizeWithCurrentAnchors 或 offsetMin/Max；sizeDelta 是差值。
修改 Size、Anchors、Pivot 都会改变 UIVertex.position不准确尺寸变化会重建顶点；纯位置变化不会改本地顶点；Anchors/Pivot 只有在改变矩形尺寸或局部原点时才需要重建。

三、Rebuild 与合批（第 19-23 页）

讲义说法判定依据 / 修正
Canvas 下 UI 元素最终会被 Batch 到同一个 Mesh大体真一个 Canvas 生成一个组合 Mesh，但按材质/纹理分成多个 SubMesh，即多个 DrawCall；不是所有元素都能合。
Batch 前按材质（Atlas）和渲染顺序重排真排序键包括 depth、material、texture、render order 等。
Batch 结果会缓存复用，直到 Canvas 被标记 dirty真官方优化指南同样强调批次缓存与 dirty 重建。
Canvas 上任何可绘制元素变化，都要重新分析整个 Canvas真“变化”包括 sprite、transform position/scale、text 等影响外观的改动。
子 Canvas 下 dirty 的子物体不会触发父 Canvas rebuild真子 Canvas 隔离父/兄弟 Canvas 的批次；但父级布局变化仍可能影响子级布局。
颜色变化通过修改顶点色实现，避免生成新的 DrawCall真颜色写入 UIVertex.color，材质/纹理不变；但仍会触发顶点重建和 Canvas 批次重建。
UIVertex.position 记录本地空间坐标真由 Graphic 在本地空间生成；Canvas 再应用变换/合批。
Rebuild 由 CanvasUpdateRegistry 监听 WillRenderCanvases 执行真当前源码使用 Canvas.willRenderCanvases += PerformUpdate；每帧渲染前执行。
Rebuild layout 前按 hierarchy 排序，根节点优先真按父节点数量升序排序；但布局计算是自底向上，控制是自顶向下。
Rebuild layout 执行 ILayoutElement / ILayoutController真CalculateLayoutInputHorizontal/Vertical + SetLayoutHorizontal/Vertical。
Rebuild graphic 调用 UpdateGeometry / UpdateMaterial真UpdateGeometry 生成顶点；UpdateMaterial 更新 CanvasRenderer 材质/纹理。
合批规则是重叠检测 + 分层合并真简化描述；实际还要看最高相交深度、材质/纹理/裁剪/A8/共面等条件。
层级号：底下能合批就同级，不能就 +1，多个取最大大体真需要补充：最高深度上有多个元素且不能全部合批时，当前元素要 +1。
合批数据最后放进 CanvasMesh 的 SubMesh真一个 Canvas 可以有多个 SubMesh / DrawCall。
为什么 rebuild layout 要优先处理根节点？讲义未答因为布局控制自顶向下（父分配空间给子），而布局计算自底向上（子先报 preferred size）。

四、优化策略（第 24-30 页）

讲义说法判定依据 / 修正
UGUI 的四个常见性能问题：填充率、Canvas 重建、顶点生成、重建次数真对应 GPU 填充、CPU Batch、CPU Geometry、dirty 频率；诊断入口不同。
减少 UI 元素可以减少排序和 Rebuild 时间真同时减少顶点、批次、Overdraw；最朴素也最有效。
动静 UI 分离到不同 Canvas真官方优化指南核心建议；代价是至少多一个批次/DrawCall。
SetActive 会触发耗时较高的 Rebuild真禁用/启用触发 OnDisable/OnEnable；整块面板可优先禁用 Canvas 组件，保留顶点缓冲。
Pixel Perfect 位移时会微调长宽，造成 layout Rebuild大体真主要是顶点按像素对齐导致的 Graphic 重建，不一定是 LayoutRebuilder 的布局计算；会影响子层级。
Animator 每帧改变元素，没有空指令检查大体真限定于 Animator 动画了 UGUI 属性；OnDidApplyAnimationProperties 会 SetAllDirty。不是所有 Animator 都必然重建。
谨慎使用 Tiled Image真会生成大量 quad；Sprite 无 border/未打包/Wrap Mode Repeat 时可用纹理平铺避免额外几何。
禁用不可见的面板真减少 Overdraw 和 DrawCall；优先禁用 Canvas 组件或 GameObject。
通过修改 Canvas 对象的 Layer 隐藏面板不通用（Overlay 下不成立）Overlay 不受相机 Culling Mask 影响；Screen Space Camera 主要看 Canvas 根 Layer。禁用 Canvas 更可靠。
不要用空 Image 做按键响应，会产生 Overdraw真空 Image 会生成白色纹理 quad，占绘制并打断合批；用不绘制的 Raycast Graphic 或已有图形。
Polygon Mode Sprites 可减少填充真用 Sprite Mesh Type = Tight + Image.useSpriteMesh；顶点数会增加，需实测。
Sliced Image 不需要中心时取消 Fill Center真只对 Sliced/Tiled 且 Sprite 有 border 的图片有效。
相同层级原则：同层 UI 可以 Batch大体真是启发式；最终看深度、遮挡、材质、纹理、裁剪、共面。
Mask 使用模板缓存，内部无法与外部合批，额外增加 2 个 DrawCall大体真Mask 用 Stencil，打断合批；“+2”是常见经验值（写入 + 清除），嵌套/内容更多时可能更多；矩形裁剪优先 RectMask2D。
隐藏的 Image（sprite 为空）也占 DrawCall 并打断合批真Image.OnPopulateMesh 在 sprite 为空时走基类，生成白色纹理 quad。
Screen Space - Camera 下，只要一个元素在屏幕内，其他屏幕外元素 DrawCall 也不减真一个 Canvas 通常是整体渲染单元；屏幕外元素仍可能参与批次。拆 Canvas / RectMask2D 更有效。
Hierarchy 穿插重叠会导致不能合批真不同图集/材质的元素夹在可合批元素之间，会切断批次。
字体图集满了会重建，按当前激活文本打包，不够再扩容大体真动态字体确实会重建/扩容；具体尺寸与时机随版本变化，不要依赖固定行为；用 Font.textureRebuilt 响应。
后备字体取自系统 Arial.ttf，安装包里不存在不准确默认字体与 Arial 有关；缺失时回退 Liberation Sans / 系统字体 / 全局 fallback；WebGL/主机不能依赖 OS 字体，需自带字体数据。
Text 重新启用时会重建网格真OnEnable 触发 SetAllDirty；长文本成本明显。
用 Font.RequestCharactersInTexture 提前生成，监听 Font.textureRebuilt 重新添加真动态字体适用；图集重建后只保留上一帧使用的字符，需重新请求。
用美术数字代替 Text经验高频变化、固定样式时有效；注意 DrawCall/Overdraw/图集；现代可用 TMP Sprite Asset。
Best Fit 代价高，会为多个字号生成图元大体真会多次排版、可能让图集膨胀；建议固定字号或限制 min/max。
描边和阴影都会增大四倍顶点假Shadow 约 2 倍；Outline 约 5 倍（1 + 4 个方向）；同时挂会更贵。
减少长文本变动，慎用 UI/Effect真长文本重建 + 顶点复制 + 图集压力叠加，容易成为热点。
ScrollView 两种填充：全量 vs 池化真元素少可全量；元素多应池化/虚拟化。
RectMask2D 可剔除窗口外元素，省去 batch真源码注释：不需要 Stencil、额外 DrawCall 更少、会剔除遮罩外元素。
Slot + LayoutElement 的简单池 / 基于位置的池经验两种都可行；注意布局组全量布局、内容高度、复用刷新和遮罩边界。
禁用无用 Raycast真GraphicRaycaster 只处理 raycastTarget = true 的 Graphic；装饰元素关闭。
子 Canvas 的 OverrideSorting 会让 Graphic Raycast 停止遍历 Transform 层级真源码中遇到 canvas.overrideSorting 会设置 continueTraversal = false。
Z 值不为零会影响渲染顺序并不能合批大体真Z 偏移会让元素不共面，通常断批；渲染顺序主要由层级/排序决定，Camera/World 模式下 Z 还影响与相机距离。
WaitingForJob / PutGeometryJobFence 说明合并网格开销巨大大体真是 UI 几何 Job / 同步等待标记；说明主线程在等几何任务，不等于必然有 bug，需看占比。
选中动画单独放到动态 Canvas经验有效隔离批次；跨 Canvas 搬对象本身也有 SetAllDirty 成本，预建独立 Canvas 更稳。
CanvasGroup 控制 alpha 淡入淡出、Interactable 控制交互真另有 blocksRaycasts；alpha=0 不是通用零成本隐藏；CanvasGroup 会产生 CanvasInjectionIndex，可能断批。

五、工具与美术规范（第 31-34 页）

讲义说法判定依据 / 修正
用 Profiler 优化真，但讲义没有展开重点看 Canvas.SendWillRenderCanvases、Canvas.BuildBatch、Graphic.OnPopulateMesh、Text.OnPopulateMesh、Font.RequestCharactersInTexture、EventSystem/Raycast。
用 FrameDebug 优化真，但讲义没有展开Frame Debugger 看 UI 批次、DrawCall、材质/纹理/Stencil 切换；结合 Overdraw 和 GPU Profiler。
规范化能减少沟通、提高协作效率经验方向正确；需要配合自动检查，否则规范容易停留在文档里。
设计模板、路径一致、图片命名、公用图集经验都对应实际成本：重复布局、资源定位、合批、内存；按项目调整，不要教条。
合理出图尺寸、图片分类经验影响包体、导入时间、显存、图集 packing；结合 Sprite Atlas / Addressables。
字体大中小分级、色值表经验减少字号/颜色数量，降低字体图集和换肤成本；现代可用 TMP Font Asset + 设计 token。

  • “大概百分之九十的窗口都在这几个模板中选择”。
  • “FairyGUI 商业案例以小游戏居多”。
  • “团队最擅长 UGUI”的具体团队背景。

这些内容可以当作“别人项目里有效的做法”，但不能直接当作行业规律。用自己的 Profiler 数据验证，才是可复现的部分。

版本差异声明

本书的结论基于 Unity 2022.3 LTS（uGUI 1.0.0）与 Unity 6（uGUI 2.x）时代的 UGUI。以下内容在不同版本里可能变化，升级后要重新验证：

  • 动态字体图集的重建尺寸、扩容策略和默认字体资源名。
  • UI Toolkit 的运行时能力、命名和与 UGUI 的互操作方式。
  • Canvas 批次构建的 Job 化程度、Profiler 标记名和 Canvas.batchingInterval 等新 API。
  • TMP 与 com.unity.ugui 包的打包关系。
  • Sprite Atlas 的打包/压缩设置和平台默认值。

如果你在项目里发现行为和本书不一致，先做两件事：确认 Unity/包版本；在项目 Library/PackageCache 里找到对应源码。文档会滞后，源码不会撒谎——但它只对当前版本负责。

最后一句：这份讲义最值得继承的不是某一条“优化技巧”，而是它把 UI 性能拆成 Canvas、RectTransform、Rebuild、合批、填充率、字体、滚动视图几条链路来思考的方式。技巧会过时，链路不会。
