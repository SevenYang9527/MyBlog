渲染优化：先找瓶颈，再谈技巧

原书第 16 章讲 Unity 中的渲染优化。它先讲移动平台的特点，再讲影响性能的因素，然后用 Unity 的分析工具定位问题，最后按“Draw Call、顶点、片元、带宽、Shader 复杂度”逐项给策略。这一章的价值不是背技巧，而是建立“瓶颈分类”的意识。

移动平台的特点

  • TBDR（Tile-Based Deferred Rendering）：很多移动 GPU 把屏幕分块，先在片上内存做深度/颜色，再写回主存。Overdraw 和带宽的影响与桌面不同。
  • 带宽敏感：纹理采样、RenderTexture 切换、全屏后处理都会吃带宽。
  • 填充率有限：大面积半透明、全屏特效、过度绘制容易先撞 GPU。
  • 精度/发热：长时间高负载会降频；不要只看峰值帧率。

影响性能的因素

因素典型症状优先动作
Draw Call 太多CPU 提交高，Profiler 里 Render 或批处理耗时高共享材质、静态/动态批处理、GPU Instancing、SRP Batcher。
顶点太多顶点处理/几何阶段高减面、LOD、遮挡剔除、合并网格。
片元/填充率太高GPU 时间高，Overdraw 严重减少全屏半透明、控制绘制顺序、降低分辨率/后处理。
带宽太高纹理采样/RT 切换多，移动端发热压缩纹理、减小纹理、减少 RT、合并 Pass。
Shader 太复杂ALU/采样/分支多简化光照、减少采样、用 LOD/变体、避免动态分支。

减少 Draw Call

  • 动态批处理：小网格、同材质可以自动合批；有顶点数/缩放限制。
  • 静态批处理：不动的物体合并成大网格；会增加内存，失去视锥剔除粒度。
  • 共享材质：不同材质实例会打断批处理；尽量共用材质/纹理。
  • GPU Instancing / SRP Batcher：现代管线的重要批处理方式；需要兼容的 Shader/材质。

减少顶点

  • 优化几何体：减面、合并、去掉看不见的面。
  • LOD：远距离用低模。
  • 遮挡剔除：被挡住的对象不提交。
  • 控制骨骼/蒙皮/顶点动画的成本。

减少片元

  • 控制绘制顺序：先画不透明，再画透明；减少 Overdraw。
  • 警惕全屏透明/粒子/后处理。
  • 减少实时光照和阴影：烘焙、光照贴图、Light Probe。
  • 用 RenderQueue/SortingOrder 控制透明排序，避免无谓重绘。

节省带宽

  • 减小纹理尺寸，使用压缩格式（ASTC/ETC2）。
  • 关闭不必要的 Mipmap/Read-Write，控制图集大小。
  • 降低 RenderTexture 分辨率，减少全屏 Pass。
  • 避免频繁的 RT 切换和 Graphics.Blit 链。

降低 Shader 复杂度

  • 用 Shader LOD 或质量档位切换简化版本。
  • 减少纹理采样、pow、normalize、动态分支。
  • 把逐像素计算移到逐顶点（如果视觉允许）。
  • 按硬件条件缩放：分辨率、阴影距离、特效质量。

工具

  • Rendering Statistics 窗口：Draw Call、三角形、顶点、SetPass。
  • Profiler：CPU/GPU、渲染模块、GC。
  • Frame Debugger：逐 DrawCall 看状态、Shader、纹理。
  • 平台 GPU 工具：RenderDoc、Xcode GPU Capture、Arm Mobile Studio 等。

现代 Unity 备注：URP/HDRP 下优先看 SRP Batcher、GPU Instancing、Render Graph、Renderer Feature 的 Pass 数；移动端仍然要关注 Overdraw、带宽和发热。原书的批处理限制（如动态批处理顶点数）在新版本可能变化，以文档为准。

本章要点：先定位 CPU/GPU/带宽，再选技巧；Draw Call、顶点、片元、带宽、Shader 复杂度是五条线；批处理不是越多越好，静态批处理会增加内存；移动端要特别关注 Overdraw 和发热。
