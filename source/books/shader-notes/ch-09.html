透明效果：渲染顺序、透明度测试与混合

原书第 8 章讲透明。透明看起来只是“让颜色带 alpha”，实际要处理渲染顺序、深度写入、混合方程和双面渲染。核心问题只有一个：不透明物体可以靠深度缓冲解决遮挡，透明物体不能。

为什么渲染顺序很重要

不透明物体通常先渲染，开启 ZWrite On 和 ZTest LEqual，后面的片元被深度测试挡住。透明物体如果也写深度，会挡住它后面的透明物体；如果不写深度，又需要从远到近排序，才能让混合结果正确。

队列典型值用途
Background1000天空盒、背景
Geometry2000不透明物体
AlphaTest2450透明度测试
Transparent3000透明混合
Overlay4000UI、镜头光晕等

透明度测试

透明度测试不混合，而是用 clip 丢弃低于阈值的片元。它通常仍然写深度，所以适合树叶、草丛、破洞等“要么完全可见、要么完全透明”的效果。

Properties
{
    _MainTex ("Texture", 2D) = "white" {}
    _Cutoff ("Alpha Cutoff", Range(0,1)) = 0.5
}

fixed4 frag (v2f i) : SV_Target
{
    fixed4 texColor = tex2D(_MainTex, i.uv);
    clip(texColor.a - _Cutoff);
    return texColor;
}

对应的渲染状态通常是 Queue = AlphaTest、ZWrite On、Cull Off（树叶等双面物体）。

透明度混合

透明度混合把片元颜色和帧缓冲颜色按 alpha 混合。最常见的是：

Tags { "Queue" = "Transparent" "RenderType" = "Transparent" }
ZWrite Off
Blend SrcAlpha OneMinusSrcAlpha

片元输出 alpha：

fixed4 frag (v2f i) : SV_Target
{
    fixed4 texColor = tex2D(_MainTex, i.uv);
    return fixed4(texColor.rgb, texColor.a * _AlphaScale);
}

ZWrite Off 让透明物体不写深度，避免挡住后面的透明物体；但这也意味着排序错误会更明显。Unity 会按物体中心/包围盒排序，复杂透明场景仍可能出现穿插错误。

双面渲染

默认 Cull Back 只画正面。透明物体（玻璃、树叶、布料）经常需要双面：

Cull Off

如果双面透明需要正确的正反面顺序，可以写两个 Pass：第一个 Cull Front 画背面，第二个 Cull Back 画正面，并分别设置队列/混合。

常见混合命令

Blend效果
Blend SrcAlpha OneMinusSrcAlpha标准 alpha 混合
Blend One One叠加/发光
Blend One OneMinusSrcAlpha预乘 alpha 的常见写法
Blend DstColor Zero正片叠底
BlendOp Add / Sub / RevSub / Min / Max自定义混合运算

透明排序的边界

  • Unity 按 Renderer 排序，不按三角形排序；一个网格内部的透明三角形仍可能出错。
  • 半透明物体互相穿插时，排序错误很难完全避免；可以用 SortingOrder、拆分网格、深度预 Pass 等方式缓解。
  • 粒子、头发、玻璃是透明问题的重灾区；不要指望一个 Blend 解决所有情况。

现代 Unity 备注：URP 的透明物体同样按队列和排序处理，但 Shader 的 Tags、光照/阴影宏不同；URP 还提供 Transparent 队列和 Depth Priming 等设置。后处理/抓屏不能用内置管线的 GrabPass，要用 _CameraOpaqueTexture 或 Renderer Feature。

本章要点：不透明靠深度，透明靠排序和混合；AlphaTest 用 clip，AlphaBlend 用 Blend + ZWrite Off；双面用 Cull Off 或两个 Pass；透明排序没有银弹，复杂场景要拆/排/预 Pass。
