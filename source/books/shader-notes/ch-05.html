Shader 需要的数学：向量、矩阵与坐标空间

原书第 4 章用“农场游戏”做引子，把 Shader 常用的数学压缩成几块：笛卡儿坐标系、点和矢量、矩阵、齐次坐标、基础变换、坐标空间、法线变换。它不追求数学系的完备性，目标是让你看懂并写出 UnityObjectToClipPos 背后的东西。

点和矢量

点是位置，矢量是方向和长度。两者在代码里都写成 float3/float4，但语义不同：点可以做平移，矢量通常不做平移；法线、切线、视线方向都是矢量。

运算公式/写法用途
加减a + b、a - b求方向、相对位置。
数乘a * s缩放长度。
点积dot(a, b) = |a||b|cosθ夹角、光照 N·L、投影。
叉积cross(a, b)求法线/切线、判断左右。
归一化normalize(a)只保留方向。
长度length(a)距离、衰减。

光照里最常见的两个点积是 dot(N, L)（法线和光照方向）和 dot(N, V)（法线和视线）。点积为负通常意味着背光/背面，需要 saturate 截到 0。

矩阵与齐次坐标

3×3 矩阵可以表示旋转和缩放，但不能表示平移；用 4×4 矩阵 + 齐次坐标（float4，w=1 表示点，w=0 表示矢量）就能把平移、旋转、缩放统一成矩阵乘法。

// 平移矩阵（列向量写法）
float4x4 T = float4x4(
    1, 0, 0, tx,
    0, 1, 0, ty,
    0, 0, 1, tz,
    0, 0, 0, 1
);

// 复合变换：先缩放，再旋转，再平移
float4x4 M = T * R * S;
float4 clipPos = mul(UNITY_MATRIX_VP, mul(unity_ObjectToWorld, v.vertex));

矩阵乘法不满足交换律，顺序很重要。Unity 的 C# 矩阵和 Shader 矩阵在存储/乘法顺序上有约定，写 Shader 时最稳的办法是用 Unity 提供的函数和宏，而不是自己拼矩阵。

MVP 与坐标空间

一个顶点从模型空间到屏幕，通常经历：

模型空间 --(M)--> 世界空间 --(V)--> 观察空间 --(P)--> 裁剪空间 --(视口)--> 屏幕空间

MVP 就是 Model × View × Projection。Unity 里最常用的封装是 UnityObjectToClipPos(v.vertex)，它等价于把模型空间顶点变换到裁剪空间，并处理不同平台的差异。老代码里的 mul(UNITY_MATRIX_MVP, v.vertex) 在新版本中不推荐直接使用。

空间常用矩阵/函数说明
模型 → 世界unity_ObjectToWorld、UnityObjectToWorldNormal法线要用逆转置矩阵，不能直接乘模型矩阵。
世界 → 观察UNITY_MATRIX_V、UnityWorldSpaceViewDir视线方向、观察空间光照。
观察 → 裁剪UNITY_MATRIX_P、UNITY_MATRIX_VP投影、裁剪空间。
模型 → 裁剪UnityObjectToClipPos最常用的顶点变换。
屏幕ComputeScreenPos、_ScreenParams屏幕坐标、后处理采样。

法线变换

法线不能直接乘模型矩阵，尤其是存在非均匀缩放时。正确做法是乘模型矩阵的逆转置矩阵；Unity 的 UnityObjectToWorldNormal 已经处理了这件事。切线通常也要用类似方式变换，并在需要时重新正交化。

float3 worldNormal = UnityObjectToWorldNormal(v.normal);
float3 worldPos = mul(unity_ObjectToWorld, v.vertex).xyz;
float3 worldViewDir = normalize(_WorldSpaceCameraPos - worldPos);

内置变量（数学篇）

变量/函数含义
unity_ObjectToWorld模型空间到世界空间。
unity_WorldToObject世界空间到模型空间。
UNITY_MATRIX_V世界空间到观察空间。
UNITY_MATRIX_P观察空间到裁剪空间。
UNITY_MATRIX_VP世界空间到裁剪空间。
_WorldSpaceCameraPos相机世界坐标。
_ScreenParams屏幕宽高、1/宽、1/高。
_ProjectionParams近裁剪面、远裁剪面等。

3×3 还是 4×4

只做方向变换（法线、切线、视线）时，3×3 足够；需要平移时用 4×4。Unity 的矩阵函数通常返回 4×4，你可以用 (float3x3) 截取左上角，但要注意非均匀缩放和平台差异。最稳的做法仍是使用 Unity 提供的 UnityObjectToWorldNormal 等封装。

现代 Unity 备注：URP/HDRP 里仍然有 TransformObjectToWorld、TransformObjectToHClip、TransformObjectToWorldNormal 等函数，命名和包含文件不同，但数学一致。不要混用内置管线的 UnityObjectToClipPos 和 URP 的包含文件。

本章要点：点是位置，矢量是方向；点积管夹角/光照，叉积管法线/切线；4×4 + 齐次坐标统一变换；MVP 把模型送到裁剪空间；法线要用逆转置；优先用 Unity 的变换函数。
