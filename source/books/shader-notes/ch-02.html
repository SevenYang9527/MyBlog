Shader 不是魔法，是 GPU 上的一段程序

原书第 1 章没有讲代码，而是先回答“Shader 是什么、为什么难、该怎么学”。它把 Shader 放进游戏程序员的技能树里：图形学、编译原理、操作系统常被戏称为“程序员的三大浪漫”，而 Shader 正好横跨图形学和编译原理——你写的是一段程序，但它最终要在 GPU 的并行架构上执行。

Shader 在做什么

从最粗的层面看，Shader 描述两件事：

  • 顶点怎么变：把模型空间的顶点变换到裁剪空间，计算法线、切线、纹理坐标等插值数据。
  • 像素怎么上色：根据插值后的数据、纹理、光照和材质参数，算出每个片元的颜色。

它不是“给模型贴一张图”的同义词。一个 Shader 可以只做纯色、可以做光照、可以做描边、可以做水波、可以做屏幕后处理；共同点是它运行在 GPU 上，输入输出由渲染管线规定。

为什么 Shader 看起来难

难的地方通常不在语法，而在三件事：

  1. 看不到中间结果：CPU 代码可以断点、打印；Shader 里不能随便 print，只能靠假彩色、Frame Debugger、RenderDoc 等工具。
  2. 并行思维：顶点着色器和片元着色器是对大量数据同时执行的，不能依赖“上一行代码先执行、下一行后执行”的全局状态。
  3. 数学和管线耦合：坐标空间、矩阵、法线变换、光照模型、阴影宏，任何一环理解错，结果都会“看起来差不多但就是不对”。

原书的建议是：先把渲染流水线和数学补起来，再写效果；不要一上来就抄一个复杂的 Shader，然后靠改参数碰运气。

学习路径

阶段目标对应章节
看懂一帧知道 CPU/GPU 怎么通信，顶点经历了哪些空间，片元经历了哪些测试。第 2 章
写出第一个 Shader理解 ShaderLab 结构、Properties、SubShader、Pass、语义。第 3、5 章
补数学向量、矩阵、齐次坐标、MVP、法线变换。第 4 章
做基础效果漫反射、高光、纹理、法线贴图、透明。第 6-8 章
做进阶效果多光源、阴影、立方体纹理、渲染纹理、动画、后处理。第 9-13 章
做风格化和优化卡通、素描、噪声、批处理、LOD、带宽。第 14-16 章

先建立三个习惯

  • 先画管线，再写代码：在纸上写出“模型空间 → 世界空间 → 观察空间 → 裁剪空间 → 屏幕空间”，标出每一步用什么矩阵。
  • 先最小可运行，再堆效果：先让一个纯色 Shader 跑起来，再加纹理、再加光照、再加阴影；每加一层都能单独验证。
  • 用工具看，不要猜：Frame Debugger 看 DrawCall 和状态，Scene 视图看 Overdraw，假彩色看数值范围，RenderDoc 看纹理和缓冲。

现代 Unity 备注：原书的学习路径仍然成立，但今天多了 Shader Graph 和 URP/HDRP。Shader Graph 适合快速做效果，但理解顶点/片元阶段、坐标空间和光照模型仍然是底层能力；否则你只能拖节点，出了问题不知道从哪查。

本章要点：Shader 是 GPU 程序，不是贴图工具；难点在不可见、并行和数学耦合；学习顺序是管线 → 结构 → 数学 → 基础效果 → 进阶效果 → 优化。
