一帧是怎么画出来的：渲染流水线

原书第 2 章是全书的地基。它先讲 CPU 和 GPU 怎么通信，再讲 GPU 内部的顶点、裁剪、屏幕映射、三角形设置、三角形遍历、片元着色和逐片元操作。你后面写的每一个 Shader，都是在这条流水线的某个阶段插进去的一段程序。

CPU 和 GPU 的分工

CPU 负责“决定画什么”：剔除、排序、设置渲染状态、提交 Draw Call。GPU 负责“把东西画出来”：执行顶点着色器、光栅化、片元着色器、深度/模板/混合。两者之间通过命令缓冲和显存交换数据。

步骤做什么常见开销
把数据加载到显存顶点、索引、纹理、常量缓冲从内存传到 GPU 可访问的显存。纹理上传、网格上传、带宽。
设置渲染状态用哪个 Shader、哪个材质、混合/深度/裁剪状态、渲染目标。状态切换、材质切换、Shader 变体。
调用 Draw Call告诉 GPU“用这个材质画这个网格”。CPU 提交开销；数量过多会成为瓶颈。

“Draw Call 越少越好”不是绝对真理，但在 CPU 受限的场景里通常成立。批处理、共享材质、GPU Instancing、SRP Batcher 都是在减少提交和状态切换的成本。

GPU 流水线

顶点着色器

顶点着色器是“逐顶点”执行的。它至少要做一件事：把顶点从模型空间变换到裁剪空间。常见输出还包括世界空间法线、切线、纹理坐标、顶点色、雾坐标等，供片元阶段插值使用。

struct appdata
{
    float4 vertex : POSITION;
    float3 normal : NORMAL;
    float2 uv : TEXCOORD0;
};

struct v2f
{
    float4 pos : SV_POSITION;
    float3 worldNormal : TEXCOORD0;
    float2 uv : TEXCOORD1;
};

v2f vert (appdata v)
{
    v2f o;
    o.pos = UnityObjectToClipPos(v.vertex);
    o.worldNormal = UnityObjectToWorldNormal(v.normal);
    o.uv = v.uv;
    return o;
}

裁剪、屏幕映射、三角形设置与遍历

  • 裁剪：把完全在视锥体外的东西去掉，把跨越视锥体的三角形切开。你通常不用手写裁剪，但要知道“裁剪空间”的 w 分量和 NDC 的关系。
  • 屏幕映射：把 NDC 的 [-1,1] 映射到屏幕像素坐标；不同图形 API 的 Y 轴方向可能不同，这是纹理坐标差异的来源之一。
  • 三角形设置：根据三个顶点计算三角形的边方程，为光栅化做准备。
  • 三角形遍历：找出三角形覆盖了哪些像素/片元，并对顶点属性做插值。

片元着色器与逐片元操作

片元着色器是“逐片元”执行的，负责算颜色。它可以使用插值后的纹理坐标、法线、世界坐标，也可以采样纹理、计算光照、做噪声。片元着色器输出颜色后，还要经过逐片元操作：

  1. 裁剪测试（如果启用）。
  2. 深度测试：比较片元深度和深度缓冲，决定是否丢弃。
  3. 模板测试：用模板缓冲做遮罩。
  4. 混合：把片元颜色和帧缓冲已有颜色按 Blend 规则混合。
  5. 写入：更新颜色/深度缓冲。

透明物体通常要关闭深度写入（ZWrite Off），并开启混合；不透明物体通常开启深度测试和写入。这个差别会在第 8 章展开。

坐标空间

空间典型变换用途
模型空间（Object/Local）模型自身的顶点坐标建模、动画、法线/切线定义
世界空间（World）unity_ObjectToWorld场景中的位置、光照、反射探针
观察空间（View/Eye）UNITY_MATRIX_V以相机为原点，方便投影
裁剪空间（Clip）UNITY_MATRIX_P投影变换，准备裁剪
屏幕空间（Screen）视口变换像素坐标、屏幕后处理

Unity 的世界空间是左手系（X 右、Y 上、Z 前）；观察空间常按右手系理解（相机看向 -Z）。不同教材的“左手/右手”说法容易混，实际写 Shader 时以 Unity 提供的矩阵和函数为准，不要自己硬编码坐标系。

容易混淆的概念

  • OpenGL / DirectX：图形 API，规定接口和部分坐标/纹理约定；Unity 会帮你处理大部分差异。
  • HLSL / GLSL / CG：着色器语言。Unity 的内置管线主要用 CG/HLSL 语法，最终编译到目标平台。
  • Draw Call：CPU 提交的一次绘制命令，不等于一个三角形，也不等于一个物体。
  • 固定管线：早期 GPU 的固定功能阶段，不可编程；现代渲染基本都用可编程 Shader。

现代 Unity 备注：URP/HDRP 使用 Scriptable Render Pipeline，渲染顺序、光照、阴影、后处理都由管线配置决定；但顶点/片元阶段、坐标空间、深度/混合这些基础没有变。理解内置管线的流水线，仍然是理解 SRP 的前提。

本章要点：CPU 决定画什么，GPU 负责画；顶点着色器做变换，片元着色器算颜色；裁剪/屏幕映射/三角形遍历是固定阶段；深度/模板/混合决定最终像素；坐标空间和矩阵是后面所有效果的基础。
