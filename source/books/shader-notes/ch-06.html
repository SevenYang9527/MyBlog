从零写一个顶点/片元着色器

原书第 5 章把前面的理论落到一个最小可运行的 Shader 上：顶点/片元着色器的基本结构、模型数据从哪里来、两个阶段怎么通信、怎么使用属性、内置文件和变量、语义、调试、平台差异和代码整洁。这一章是后面所有效果的模板。

最小结构

Shader "Custom/Minimal"
{
    Properties
    {
        _MainTex ("Texture", 2D) = "white" {}
        _Color ("Tint", Color) = (1,1,1,1)
    }

    SubShader
    {
        Tags { "RenderType" = "Opaque" "Queue" = "Geometry" }

        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #include "UnityCG.cginc"

            sampler2D _MainTex;
            float4 _MainTex_ST;
            fixed4 _Color;

            struct appdata
            {
                float4 vertex : POSITION;
                float2 uv : TEXCOORD0;
            };

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = TRANSFORM_TEX(v.uv, _MainTex);
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                return tex2D(_MainTex, i.uv) * _Color;
            }
            ENDCG
        }
    }
}

模型数据从哪里来

顶点数据由网格提供，常见语义：

语义含义常见用途
POSITION模型空间顶点位置顶点变换
NORMAL模型空间法线光照、法线贴图
TANGENT切线（通常带 handedness）切线空间、法线贴图
TEXCOORD0..n纹理坐标/额外数据UV、光照贴图 UV、自定义数据
COLOR顶点色着色、遮罩

顶点着色器和片元着色器怎么通信

顶点着色器输出一个结构体（常叫 v2f），片元着色器接收同一个结构体。顶点阶段算好的数据会经过光栅化插值，片元阶段拿到的是插值后的值。常见字段：

  • SV_POSITION：裁剪空间位置，必须由顶点着色器输出。
  • TEXCOORD0..n：UV、世界坐标、法线等自定义插值数据。
  • COLOR0：顶点色。

插值不是免费的：字段越多，带宽和寄存器压力越大。只传片元真正需要的字段。

属性与纹理的 ST

纹理属性 _MainTex 会自动生成 _MainTex_ST，四个分量是 (TilingX, TilingY, OffsetX, OffsetY)。手写 uv * _MainTex_ST.xy + _MainTex_ST.zw 和 TRANSFORM_TEX 等价，但后者更清晰。

float2 uv = TRANSFORM_TEX(v.uv, _MainTex);
// 等价于：
// float2 uv = v.uv * _MainTex_ST.xy + _MainTex_ST.zw;

内置文件和变量

  • UnityCG.cginc：最常用，包含 UnityObjectToClipPos、UnityObjectToWorldNormal、TRANSFORM_TEX、_Time 等。
  • Lighting.cginc：内置光照模型和 _LightColor0、_WorldSpaceLightPos0。
  • AutoLight.cginc：阴影/光照衰减宏，如 SHADOW_COORDS、TRANSFER_SHADOW、UNITY_LIGHT_ATTENUATION。

语义与复杂变量

语义告诉编译器“这个变量从哪来、到哪去”。顶点输入用 POSITION/NORMAL/TEXCOORD0，顶点输出到片元用 SV_POSITION 和自定义 TEXCOORD，片元输出用 SV_Target。复杂类型（结构体）可以承载多个语义，但每个字段都要有语义。

调试与平台差异

  • 假彩色：把法线、UV、深度映射成颜色，直观看出范围是否正确。
  • Visual Studio / Rider：可以附加调试，但 Shader 断点能力有限。
  • Frame Debugger：看 DrawCall、Shader、纹理、渲染状态。
  • 平台差异：纹理坐标原点（DirectX/OpenGL）、语义大小写、精度、裁剪空间 Z 范围等。Unity 的宏会处理大部分差异，但自定义代码要小心。

代码整洁

  • 明确精度：顶点位置/UV 用 float，颜色/法线可用 half；不要滥用 fixed。
  • 避免不必要的 normalize、pow、分支和循环；片元阶段尤其昂贵。
  • 不要除以 0；用 max(denominator, 1e-5) 保护。
  • 把重复计算提到顶点阶段；但不要为了省一点计算传过多插值字段。

现代 Unity 备注：fixed 在现代 GPU 上通常不再是独立精度，建议用 half/float 明确意图。URP 的包含文件和变换函数不同（TransformObjectToHClip 等），但最小结构、语义和 v2f 思路一致。

本章要点：顶点/片元着色器是模板；appdata 接模型数据，v2f 传插值数据；纹理用 TRANSFORM_TEX；内置文件提供变换/光照/阴影；调试靠假彩色和 Frame Debugger；精度、分支、除法都要克制。
