资产（Assets）

资产管线会极大地影响应用程序的性能。一位经验丰富的技术美术可以帮助团队定义并落实资产格式、规格与导入设置。

不要依赖默认设置。使用平台专用的覆盖（override）标签页来优化纹理和网格几何体等资产。设置不当可能导致更大的构建体积、更长的构建时间以及糟糕的内存占用。可以考虑使用 Presets 功能为特定项目定制基线设置，以确保获得最优设置。

更多细节请参阅这份美术资产最佳实践指南，或查看 Unity Learn 上关于移动应用 3D 美术优化的课程。

正确导入纹理

你的大部分内存很可能都被纹理所占用，因此这里的导入设置至关重要。总体而言，请遵循以下准则：

  • 降低 Max Size：使用能产生视觉上可接受效果的最小设置。这是非破坏性的，可以快速降低纹理内存。
  • 使用 2 的幂（POT）：对于移动端纹理压缩格式（PVRTC 或 ETC），Unity 要求纹理尺寸为 2 的幂。
  • 为纹理打图集：将多张纹理放进一张纹理中可减少绘制调用并加速渲染。使用 Unity Sprite Atlas 或第三方工具 Texture Packer 为纹理打图集。
  • 关闭 Read/Write Enabled 选项：启用该选项会在 CPU 和 GPU 可寻址内存中各创建一份副本，使纹理的内存占用翻倍。多数情况下应保持禁用。如果你在运行时生成纹理，请通过 Texture2D.Apply 强制实现这一点，并将 makeNoLongerReadable 设为 true。
  • 禁用不必要的 Mip Maps：对于在屏幕上尺寸保持一致的纹理（例如 2D 精灵和 UI 图形），不需要 Mip Maps（对于与相机距离不断变化的 3D 模型，请保留 Mip Maps 启用）。

压缩纹理

请考虑以下两个使用相同模型和纹理的示例。左侧的设置消耗的内存几乎是右侧的八倍，却在视觉质量上几乎没有收益。

在 iOS 和 Android 上都使用自适应可缩放纹理压缩（ASTC）。绝大多数在研游戏的目标最低规格设备都支持 ASTC 压缩。

唯一的例外是：

  • 面向 A7 及更低设备（例如 iPhone 5、5S 等）的 iOS 游戏——使用 PVRTC。
  • 面向 2016 年之前设备的 Android 游戏——使用 ETC2（Ericsson Texture Compression）。

如果 PVRTC 和 ETC 等压缩格式的质量不够高，而 ASTC 在你的目标平台上又没有得到完全支持，可以尝试用 16 位纹理代替 32 位纹理。

有关各平台推荐纹理压缩格式的更多信息，请参阅手册。

调整网格导入设置

与纹理类似，如果不谨慎导入，网格也会消耗过多内存。要将网格的内存消耗降到最低：

  • 压缩网格：激进的压缩可以减少磁盘空间（但运行时的内存不受影响）。注意网格量化可能造成精度损失，因此请试验不同的压缩级别，看看哪种适合你的模型。
  • 禁用 Read/Write：启用该选项会在内存中复制网格，一份副本保存在系统内存，另一份保存在 GPU 内存。多数情况下应将其禁用（在 Unity 2019.2 及更早版本中，该选项默认勾选）。
  • 禁用 rigs 和 BlendShapes：如果你的网格不需要骨骼动画或 blendshape 动画，请尽可能禁用这些选项。
  • 尽可能禁用 normals 和 tangents：如果你确定网格的材质不需要法线或切线，取消勾选这些选项可以进一步节省内存。

检查多边形数量

分辨率更高的模型意味着更高的内存占用，也可能带来更长的 GPU 耗时。你的背景几何体真的需要五十万个多边形吗？考虑在你选用的 DCC 工具中削减模型。删除相机视角中看不到的多边形。用纹理和法线贴图来表现细节，而不是用高密度网格。

使用 AssetPostprocessor 自动化导入设置

AssetPostprocessor 让你可以接入导入管线，在导入资产之前或导入时运行脚本。这样你就能在导入模型、纹理、音频等内容之前和/或之后自定义设置，方式与 Presets 类似，只不过是通过代码实现。想了解更多流程，请观看我们在 GDC 2023 的演讲《游戏创作各阶段的技术技巧》。

Unity DataTools

Unity DataTools 是 Unity 提供的一套开源工具集合，旨在增强 Unity 项目中的数据管理与序列化能力。它包含分析和优化项目数据的功能，例如识别未使用的资产、检测资产依赖关系以及缩减构建体积。

使用可寻址资源系统

可寻址资源系统（Addressable Asset System）提供了一种简化方式来管理内容，通过“地址”或别名加载 AssetBundle。这套统一的系统可以从本地路径或远程内容分发网络（CDN）异步加载。

如果你把非代码资产（模型、纹理、Prefab、音频，甚至整个场景）拆分到 AssetBundle 中，就可以将它们分离为可下载内容（DLC）。

然后，使用 Addressables 为你的移动应用创建更小的初始构建。Cloud Content Delivery 让你可以托管游戏内容，并在玩家推进游戏的过程中向他们分发。
