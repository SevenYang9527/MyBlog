第 7 章 通用服务端框架

原书把服务端拆成“网络模块 + 消息分发 + 玩家数据 + 数据库 + 登录注册”。服务端监听端口，接受客户端连接，为每个连接维护 ClientState；收到消息后按协议 ID 分发到处理函数，再读写玩家数据/数据库。

架构要点：Acceptor/Listener、连接管理、消息队列、定时器、心跳、协议编解码、玩家/房间数据、MySQL 持久化、登录注册、异常/断线清理。服务端要能同时处理很多连接，且不能让一个慢客户端拖垮全局。

这一章把“单机 Echo”变成“多人在线服务”：连接、状态、持久化、业务逻辑开始分层。

原书脉络

  • 7.1 服务端架构/模块划分/游戏流程。
  • 7.2 Json 编解码；7.3 网络模块（ClientState、监听、多路复用、消息处理、Timer）。
  • 7.4 心跳；7.5 玩家数据结构；7.6 MySQL；7.7 数据库模块；7.8 登录注册。

关键实现：ClientState 与数据库

每个连接一个 ClientState：Socket、接收缓冲、玩家数据、最后心跳时间。消息分发到 Handler；数据库操作不要阻塞网络线程，用连接池/异步，并且所有 SQL 参数化。

public class ClientState
{
    public Socket Socket;
    public ByteArray Buffer = new();
    public PlayerData Player;
    public DateTime LastPing;
}

// 参数化查询（示意，使用 MySqlConnector）
public async Task<bool> IsAccountExist(string account)
{
    using var conn = new MySqlConnection(connStr);
    await conn.OpenAsync();
    using var cmd = new MySqlCommand("select 1 from account where account=@a limit 1", conn);
    cmd.Parameters.AddWithValue("@a", account);
    return await cmd.ExecuteScalarAsync() != null;
}

常见坑

  • 字符串拼接 SQL → SQL 注入；必须参数化。
  • 明文/简单 MD5 存密码；用 bcrypt/Argon2/PBKDF2 + salt。
  • 网络线程同步查库，慢查询拖死所有客户端；异步/连接池/缓存。
  • 登录成功但重复登录/顶号/断线重连没处理；需要会话表/心跳/踢人策略。

练习

把登录改成 token + 过期时间；加 Redis 缓存在线会话；用 EXPLAIN 检查账号查询索引。

2026 更新：现代服务端可用 ASP.NET Core/gRPC、Orleans/Akka、Redis、PostgreSQL、EF Core/Dapper、Docker/K8s；加 JWT/OAuth2、限流、可观测性（日志/指标/追踪）、SQL 参数化、服务端权威。

本章要点：服务端 = 网络模块 + 分发 + 玩家数据 + DB；Listener/ClientState/Handler/Timer/心跳/断线清理；登录注册/房间/战斗分层；生产化要加鉴权/限流/可观测性。
