第 5 章 深入了解 TCP：连接、参数与异常

原书从 TCP/IP 分层讲到“从应用到铜线”：应用层、传输层、网络层、网络接口。TCP 通过三次握手建立连接（SYN/SYN-ACK/ACK），通过序列号/确认/重传保证可靠，通过四次挥手/FIN/RST 关闭。

常用参数：ReceiveBufferSize、SendBufferSize、NoDelay（禁用 Nagle）、TTL、ReuseAddress、LingerState。关闭时机很重要：半关闭、RST、未读数据、TIME_WAIT 都会影响“为什么连接关了但端口还占着”。

异常处理与心跳：网络断开、超时、对端崩溃、NAT 回收、移动网络切换都需要检测；心跳（PING/PONG）和超时重连是客户端/服务端的常规能力。

原书脉络

  • 5.1 从 TCP 到铜线：应用层/传输层/网络层/网络接口。
  • 5.2 连接建立、数据传输、连接终止。
  • 5.3 常用参数：ReceiveBufferSize、SendBufferSize、NoDelay、TTL、ReuseAddress、LingerState。
  • 5.4 Close 的恰当时机；5.5 异常处理；5.6 心跳机制。

关键实现：参数与心跳

实时游戏通常开 NoDelay 降低小包延迟；缓冲区不是越大越好，过大可能增加排队延迟。心跳要能区分“暂时没消息”和“连接已死”，超时后主动关闭并重连。

var client = new TcpClient();
client.NoDelay = true;
client.ReceiveBufferSize = 64 * 1024;
client.SendBufferSize = 64 * 1024;
client.Client.SetSocketOption(SocketOptionLevel.Socket, SocketOptionName.KeepAlive, true);

// 心跳（简化）：每 5 秒发 PING，15 秒没 PONG 就断开
async Task Heartbeat(NetworkStream stream, CancellationToken ct)
{
    while (!ct.IsCancellationRequested)
    {
        await SendFrame(stream, Encoding.UTF8.GetBytes("PING"), ct);
        await Task.Delay(5000, ct);
        if (DateTime.UtcNow - lastPong > TimeSpan.FromSeconds(15))
        {
            client.Close();
            break;
        }
    }
}

常见坑

  • 只靠 TCP KeepAlive 检测应用层假死；长连接要应用层心跳。
  • 关闭时还有未读数据/未发数据，导致 RST 或丢消息；先停写、再读干净、再关闭。
  • LingerState 设置不当导致关闭阻塞或 RST。
  • 重连没有退避/上限，服务器故障时被客户端打爆。

练习

用 tc/代理工具模拟 200ms 延迟、5% 丢包、断线 10 秒，观察心跳/重连行为；把超时时间做成可配置。

2026 更新：现代服务常用 TLS 1.3、QUIC（0-RTT/连接迁移）、TCP KeepAlive、负载均衡 idle timeout、指数退避重连；移动网络切换/弱网下要区分“暂时卡顿”和“真断线”。
