第 8 章 完整大项目《坦克大战》

原书用《坦克大战》把前面所有模块串起来：登录注册、房间系统、战斗系统；坦克模型/资源管理器、坦克类、行走控制、爬坡、相机跟随、旋转炮塔、发射炮弹、摧毁敌人、生命值/特效。

客户端负责输入、表现、预测；服务端负责权威状态、命中/伤害/胜负。资源管理要处理模型、材质、预设、图集、加载/释放；坦克移动要处理地形/物理/同步；相机和炮塔是“本地表现”与“服务器状态”的分界。

这一章的核心是“把网络、战斗、UI、资源组织成一个可玩的闭环”。

原书脉络

  • 8.1 游戏功能：登录注册、房间、战斗；8.2 坦克模型；8.3 资源管理器。
  • 8.4 坦克类；8.5 行走控制；8.6 爬坡；8.7 相机跟随；8.8 旋转炮塔。
  • 8.9 发射炮弹；8.10 摧毁敌人、生命值、特效。

关键实现：移动与同步的分层

客户端用输入驱动本地坦克，服务端保存权威位置/朝向/血量；SyncTank 负责把服务器状态插值到表现层。移动/炮塔/子弹/特效要拆成独立组件，方便复用和优化。

public class Tank : MonoBehaviour
{
    public float speed = 6f;
    public float turnSpeed = 90f;
    public Transform turret;

    public void ApplyInput(float move, float turn, float turretYaw, float dt)
    {
        transform.Translate(0, 0, move * speed * dt, Space.Self);
        transform.Rotate(0, turn * turnSpeed * dt, 0);
        turret.localRotation = Quaternion.Euler(0, turretYaw, 0);
    }
}

public class SyncTank : MonoBehaviour
{
    public Vector3 targetPos;
    public Quaternion targetRot;

    void Update()
    {
        transform.position = Vector3.Lerp(transform.position, targetPos, 10f * Time.deltaTime);
        transform.rotation = Quaternion.Slerp(transform.rotation, targetRot, 10f * Time.deltaTime);
    }
}

常见坑

  • 客户端直接决定命中/伤害；服务端必须校验射线/距离/冷却。
  • 相机 LateUpdate/插值没做好，移动抖动；物理和表现不同步。
  • 爬坡用 Transform 硬移，穿模/抖动；用 CharacterController/物理或射线贴地。
  • 子弹/特效频繁 Instantiate/Destroy；用对象池。

练习

给坦克加“炮塔独立瞄准 + 车体移动”；用对象池管理炮弹/爆炸；把相机改成 Cinemachine 并对比抖动。

2026 更新：Unity 6/URP、Addressables、Cinemachine、Input System 是更现代的工程组合；物理/移动要区分“客户端表现”和“服务端权威”，动作游戏考虑预测/回滚/确定性物理。

本章要点：坦克大战串起登录/房间/战斗；客户端输入/表现/预测，服务端权威状态/命中/胜负；资源/物理/相机/炮塔/特效要分层；现代工程用 URP/Addressables/Cinemachine/Input System。
