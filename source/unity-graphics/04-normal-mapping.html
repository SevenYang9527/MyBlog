一句话

法线贴图不是凹凸，是朝向。它用 RGB 三个通道存一个单位向量的三个分量（颜色 = 法线 × 0.5 + 0.5），所以「完全平坦」的编码是 (0.5, 0.5, 1) —— 也就是法线贴图那种标志性的淡紫蓝色。

先纠正一个普遍误解

很多人以为法线贴图是「把模型的凹凸信息画上去」。不是的。它完全不改变几何：

它会变的

  • 光照的计算结果（因为法线变了）
  • 高光的位置和形状
  • 物体看起来的「粗糙 / 平滑」

它不会变的

  • 轮廓（silhouette）——侧着看还是平的
  • 遮挡关系——不会真的挡到别的东西
  • 阴影的形状

所以法线贴图最适合「细节密集、但轮廓简单」的东西：砖墙、金属板、皮革、地面。一旦你需要「侧着看也有起伏」，就得上视差贴图（Parallax）、置换贴图（Displacement）或者干脆加模型面数。

一个向量，怎么塞进一张图

法线的三个分量范围是 −1 ~ 1，而颜色通道只有 0 ~ 1。所以标准做法是先做一次「压缩映射」：

编码与解码

编码：颜色 = 法线 × 0.5 + 0.5
解码：法线 = 颜色 × 2 − 1

于是「完全平坦、朝外」的法线 (0, 0, 1) 会变成 (0.5, 0.5, 1)，也就是 RGB (128, 128, 255) —— 打开一张法线贴图看到的那片淡紫蓝色，本质上是「这里没有凹凸」。

所以法线贴图必须存成 Linear

法线不是颜色，是数据。如果导入时勾了 sRGB，引擎会自动做一次 gamma 解码，把 128 变成 55 左右——法线就全错了。表现是：表面发灰、发亮、光照永远偏一个方向。Unity 的 Texture Type = Normal map 会自动关掉 sRGB，但如果你手动建 RenderTexture 或者从代码里 LoadImage，就得自己记得设 Linear。

为什么非要「切线空间」

法线贴图里存的是切线空间下的法线，不是世界空间。这是一个非常聪明的偷懒：

如果存世界空间如果存切线空间（实际做法）
墙转了 90°，贴图就废了，得重做一张同一张砖墙贴图能贴在任何朝向的面上
角色动画一弯腰，法线全错，因为表面转了切线跟着表面一起变形，始终正确
UV 平铺 4×4 后，法线方向对不上平铺不影响切线空间，直接重复采样即可
大部分法线值分布在整个球面上，压缩率差绝大部分法线接近 (0,0,1)，压缩友好

代价是：使用时必须把切线空间法线转回世界空间，才能和世界空间的光方向做点乘。这个转换就是 TBN 矩阵：

TBN 矩阵

世界法线 = T × n.x + B × n.y + N × n.z

其中 n 是从贴图解码出来的切线空间法线。T、B、N 这三根轴由模型数据提供。

TBN 从哪来

顶点数据里本来只有法线（NORMAL）。T（切线）和 B（副切线）不是模型文件自带的，而是导入时根据 UV 算出来的——因为「沿 U 方向」这个方向只有在有了 UV 之后才有意义。B 则可以直接由 cross(N, T) × T.w 得到（那个 w 分量存的是手性符号，用来兼容镜像 UV）。

Unity 的导入设置

模型文件（FBX/OBJ）的 Import Settings → Normals 设为 Import 或 Calculate 时，Tangents 也要一起设。如果显示 Missing，法线贴图就会退化成「直接用顶点法线」，看起来完全没有凹凸。这是「法线贴图不生效」的第一大原因。

Unity 对照：导入、材质、Shader

贴图导入设置

设置项应该选什么为什么
Texture TypeNormal map自动关掉 sRGB，并按法线方式压缩
Create from Grayscale普通法线图关掉；从高度图生成时打开它是把灰度图当高度来求导生成法线

Shader 里怎么用

HLSL · 内置管线 采样、解码、转到世界空间 
struct v2f
{
    float4 pos      : SV_POSITION;
    float2 uv       : TEXCOORD0;
    float3 normalWS : TEXCOORD1;
    float4 tangentWS: TEXCOORD2;   // xyz = 切线，w = 手性符号
};

// 顶点着色器里：把法线和切线都转到世界空间
o.normalWS  = UnityObjectToWorldNormal(v.normal);
o.tangentWS = float4(UnityObjectToWorldDir(v.tangent.xyz), v.tangent.w);

// 片元着色器里：
// 1. 采样并解码：(0..1) → (0,0,1) 附近的单位向量
float3 nTS = UnpackNormal(tex2D(_BumpMap, i.uv));
nTS.xy *= _BumpScale;                       // 强度，1 是原始强度

// 2. 构造 TBN 并转世界空间
float3 N = normalize(i.normalWS);
float3 T = normalize(i.tangentWS.xyz - N * dot(N, i.tangentWS.xyz));  // 正交化
float3 B = cross(N, T) * i.tangentWS.w;
float3x3 TBN = float3x3(T, B, N);
float3 normalWS = normalize(mul(nTS, TBN));
HLSL · URP 17 URP 里更省事：NormalWS 在顶点阶段就准备好了 
// 顶点输入结构用 Attributes，输出用 Varyings
// Varyings 里带 normalWS 和 tangentWS（URP 的 ShaderVariablesFunctions 会自动填充）
float3 nTS = UnpackNormalScale(
    SAMPLE_TEXTURE2D(_BumpMap, sampler_BumpMap, uv), _BumpScale);

float3 N = normalize(input.normalWS);
float3 T = normalize(input.tangentWS.xyz - N * dot(N, input.tangentWS.xyz));
float3 B = cross(N, T) * input.tangentWS.w;

float3 normalWS = TransformTangentToWorld(nTS, half3x3(T, B, N));

不想写代码？Shader Graph 有现成的

  • Normal Map 节点：输入一张 Normal 贴图和 Strength，直接输出切线空间法线（它内部就是 Unpack + 缩放）。
  • Normal From Texture 节点：从高度图（灰度）现场求出法线，适合程序化材质。
  • Normal Blend 节点：把两张法线叠在一起（做细节叠加时用）。
  • 最后接 Normal (World) 或 Normal (Tangent) 到光照节点，注意别接错空间。

绿通道：DirectX 和 OpenGL 的历史遗留问题

切线空间里，绿通道（G）代表「沿 V 方向的倾斜」。但两家图形 API 对 V 轴朝上还是朝下没有统一约定：

来源绿通道约定Unity 里怎么办
DirectX（3ds Max、Marmoset、Substance 默认）Y 轴向下直接导入通常就对
OpenGL（Blender 默认、老教程）Y 轴向上导入设置勾 Flip Green Channel

怎么一眼判断反没反

在场景里放一盏斜上方的方向光，看砖墙：本该被照亮的上半边如果反而更暗，就是反了。翻转绿通道后立刻正常。

六个坑

症状原因修法
法线贴图完全没效果 模型没有切线数据 模型导入设置里把 Tangents 设为 Calculate / Import
表面发灰、整体偏亮，光照方向怪 贴图被当成 sRGB 颜色 Texture Type 设为 Normal map；代码加载时用 Linear
凸起变凹陷 绿通道约定不一致 导入设置勾 Flip Green Channel
UV 接缝处一条亮线 / 黑缝 模型在该处 UV 断开，切线不连续 接缝处做切线平滑（建模端），或接受轻微瑕疵
高光碎成一片噪点 强度（Bumpiness / _BumpScale）过大 降到 1 附近，或者用更平缓的法线图
Albedo 和法线的平铺不一致 两张贴图的 Tiling 不同 统一 Tiling；或写两套 UV

自测：三题

自测 · 3 个问题（先自己答，再展开）
  1. 一张纯淡紫色 RGB(128,128,255) 的贴图贴上去，会有什么效果？ 没有任何凹凸效果——这正好是「完全平坦」的编码。它等价于告诉引擎「每个像素的法线都朝外」，也就是什么也没改。
  2. 为什么法线贴图里几乎看不到纯黑或纯白？ 因为存的是单位向量的一半区间，绝大多数法线接近 (0,0,1)，编码后落在 (128,128,255) 附近。纯黑 (0,0,0) 解出来是 (−1,−1,−1)，不是合法的单位向量。
  3. 物体缩放成 2 倍后，法线贴图的凹凸感会变吗？ 几何会被拉伸，但法线贴图的凹凸强度不变（因为它按 UV 采样）。所以非均匀缩放会让细节「变扁」而光照仍然按原强度计算，观感会不匹配——一般会给材质加个按缩放补偿的 BumpScale。
