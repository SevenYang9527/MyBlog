Unity 开发者的图形学补课

把 LearnOpenGL 的 5 章，
翻译成 Unity 的语言

你不需要手写渲染器。但要写自定义 Shader、看懂 URP 的设置、解释「为什么这里高光炸了」，你需要坐标系统、摄像机、光照、法线贴图、帧缓冲这五件事。这一站把它们从 C++/OpenGL 搬到 Unity 的语境里重讲一遍：少了 90% 的样板代码，只留下真正会用到的那部分。

5章核心概念
≈3h通读全站
0行 C++ 要写
12张手绘图解
先看结论

这 5 章在 Unity 里的真实用途只有三件事：写 Shader 时知道自己在哪个空间里算、调光照时知道每个参数在对哪个数学项下手、做后处理时知道画面从哪来又要到哪去。除此之外的 OpenGL 细节，Unity 全包了。

为什么只留 5 章

LearnOpenGL 是一套「从零手写渲染器」的教程：60 多节，其中一半在教你怎么创建窗口、怎么把顶点塞进 VBO、怎么用 Assimp 解析 fbx。这些在 Unity 里对应的是点一下 Play 和把模型拖进 Project。

剩下的内容里，真正会反复影响你「能不能把画面调对」的，是下面这张表里的东西：

原教程章节它其实在讲什么Unity 里你会在什么时候撞上它
坐标系统 顶点从模型空间一路变到屏幕像素的五个空间 Shader 里 Space 选 Object 还是 World；模型旋转后法线不对；UI 和 3D 坐标对不上
摄像机 观察矩阵、投影矩阵、视锥体 FOV 调完画面变形；物体贴脸就消失（近裁剪面）；WorldToScreenPoint 算出来偏了
基础光照 环境光 + 漫反射 + 高光的 Blinn-Phong 模型 想调「金属感」「塑料感」；写 Shader Graph 里那条 Dot Product；Light 的 Intensity 到底乘在哪
法线贴图 用 RGB 存每个像素的表面朝向；切线空间 导入法线贴图后表面发灰；贴图接缝一条亮线；移动端上「凹凸感全没了」
帧缓冲 离屏渲染 + 全屏后处理 做描边、模糊、Bloom、屏幕特效；URP 里写 Renderer Feature；OnRenderImage 突然不生效

被砍掉的部分

窗口创建、GLAD/GLEW、VBO/VAO/EBO、Assimp 模型加载、几何着色器、模板测试、实例化、PBR 的 IBL 细节——这些要么 Unity 做了，要么属于「做引擎」而不是「做游戏」的范畴。真需要时再回头查原教程即可，那时你已经有了本站建立的空间感。

五章内容

CHAPTER 01

坐标系统

局部 → 世界 → 观察 → 裁剪 → 屏幕。一个顶点要走五段路才上屏，Unity 只让你操心第一段。含完整空间对照表与手搓 MVP 的验证代码。

开始阅读 → CHAPTER 02

摄像机

摄像机不是眼睛，是一个把世界反向搬到你面前的矩阵。顺带讲清 FOV 是垂直还是水平、近裁剪面为什么不能设 0.01、视锥体怎么算。

开始阅读 → CHAPTER 03

基础光照

N、L、V、H 四个向量决定一切。把 Blinn-Phong 的三项拆开，逐项对应到 Unity 的 Light 组件、URP 的 Lit 材质和 Shader Graph 节点。

开始阅读 → CHAPTER 04

法线贴图

法线贴图不是「凹凸」，是「每个像素的朝向」。RGB 怎么编码向量、切线空间为什么必须存在、绿通道为什么会被翻转。

开始阅读 → CHAPTER 05

帧缓冲

把场景画到一张能当纹理用的画布上，再贴回屏幕——这就是后处理。从 RenderTexture 到 URP 的 Renderer Feature，附一个可跑的边缘检测。

开始阅读 → 路线建议

如果你只有 3 小时

按 01 → 03 → 04 读，跳过 02 和 05。这三章覆盖了 80% 的「画面不对」场景。第二天再补 02，做后处理时再补 05。

怎么用这个站

01 先看「一句话」

每章开头都有一张蓝色卡片，用一句话把该章的全部价值说完。如果你只想快速建立直觉，读完五张卡片就够了。

02 再看图

所有图都是手绘 SVG，可以在深色模式下看清。图的目的是让你在脑子里建立「空间/向量/管线」的画面感，比公式管用。

03 最后做对照

每章都有一个蓝色的「Unity 对照」块：同一个概念在 Unity 里叫什么、在哪个面板、用哪个 API。这是本站和原教程最大的区别。

三种读法

读法耗时适合
速通：只看「一句话」+ 图 + 「坑」40 分钟只想有个整体印象，先知道有哪些概念存在
标准：全站通读，代码只看不敲约 3 小时准备写第一个自定义 Shader，需要知道每个参数的含义
动手：每章的代码块都跑一遍，自测全做1–2 天正在做后处理或自定义光照，需要能改能用

阅读前提

会打开 Unity、知道 GameObject 和 Component 的关系、能看懂 C# 的类和字段，就够开始了。数学只需要「向量点乘」这一条：a·b = |a||b|cosθ，其余章节遇到会现场解释。

一个心态上的建议

读的时候不要试图「记住公式」。你要建立的是判断力：看到画面偏暗，知道该怀疑环境光还是法线；看到边缘有锯齿状的亮线，知道那是法线贴图接缝。判断力来自对照表 + 踩坑，不来自推导。
