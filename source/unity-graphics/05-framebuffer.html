第 05 章 · 帧缓冲

把画面，画到一张画布上

前面四章都在讲「怎么把像素画对」。这一章讲一个完全不同的事：画到哪儿。默认情况下画面直接进屏幕，你碰不到它；但只要改成一个离屏缓冲，这张画面就变成了一张普通纹理——于是可以模糊、描边、调色、再贴回去。

一句话

帧缓冲就是一块能当纹理用的画布。把场景画到它上面，再把这块画布贴到一个铺满屏幕的方块上，在贴的过程中对每个像素做点数学——这就是后处理的全部原理，Bloom、描边、色差、故障风，无一例外。

为什么不能直接在屏幕上做处理

默认情况下，GPU 画完一帧就直接把它送进显示器的缓冲区。这个过程是「输出」，不是「输入」——你没法在同一个 Pass 里既画又读。

要做二次处理，只能换个思路：

  1. 先把场景画到一块不在屏幕上的缓冲区（离屏渲染）
  2. 这块缓冲区的内容可以被当成普通纹理来采样
  3. 最后画一个铺满屏幕的方块，用自定义 Shader 采样它、加工它、输出到屏幕

这就是原始教程里 帧缓冲（FBO）做的事，也是所有后处理框架的地基。

帧缓冲里有什么

一个帧缓冲不只有颜色，它是一组附件（attachment）：

附件存什么Unity 里有什么用
颜色 Color每个像素的 RGBARenderTexture 本体图像本身
深度 Depth每个像素离相机多远new RenderTexture(w, h, 24) 里的 24深度测试、雾、深度后处理（景深、边缘光）
模板 Stencil一个 8 位标记通常在 depth 里一起分配遮罩、描边、UI 裁剪

深度位数是个开关

new RenderTexture(w, h, 24) 的第三个参数是深度位数。写成 0 表示不要深度——此时物体不分前后，会按绘制顺序互相覆盖。做纯 2D 后处理可以省掉它（省显存和带宽），但只要场景里有 3D 遮挡，就必须给。

后处理 = 全屏方块 + 采样 + 数学

所谓「全屏后处理」，抽象到最简单就是：

  1. 画一个刚好挡住整个屏幕的方块（Unity 的 Graphics.Blit 帮你做了）
  2. 它的每个像素用 UV 去采样源纹理
  3. 把采样到的颜色做点运算

复杂的效果只是「运算」更花哨。比如模糊，就是对周围一圈像素做加权平均——这个权重的形状叫卷积核：

Unity 对照：三条路线

路线适用管线难度什么时候用
RenderTexture + Graphics.Blit全都行低监控画面、UI 里的 3D 预览、手动接管渲染
OnRenderImage仅内置管线低老项目、快速原型（URP 里不生效！）
Renderer FeatureURP中新项目、要跟 URP 的渲染流程协作
Full Screen Pass Renderer FeatureURP 14+最低只想写个 Shader Graph 做全屏效果

路线一：RenderTexture（最通用）

C# 把相机画面渲染到一张纹理，再当贴图用 
using UnityEngine;

public class CameraToTexture : MonoBehaviour
{
    public Camera cam;
    public Renderer screenQuad;   // 场景里一个铺开的 Quad
    public int width = 512;
    public int height = 512;

    RenderTexture rt;

    void Start()
    {
        // 参数：宽、高、深度位数（0 = 不要深度）
        rt = new RenderTexture(width, height, 24);
        rt.name = "MonitorRT";
        rt.Create();                       // 显式创建，避免延迟分配

        cam.targetTexture = rt;            // 相机不再画到屏幕，画进这张纹理
        screenQuad.material.mainTexture = rt;   // 这块 Quad 显示它
    }

    void OnDestroy()
    {
        if (rt != null)
        {
            rt.Release();                  // 必须释放，否则显存泄漏
            Destroy(rt);
        }
    }
}

路线二：OnRenderImage（内置管线）

C# 挂在相机上，一行完成「贴一块材质」 
using UnityEngine;

[RequireComponent(typeof(Camera))]
public class SimplePostFX : MonoBehaviour
{
    public Material effectMaterial;

    // src = Unity 已经画好的画面，dst = 要输出的地方
    void OnRenderImage(RenderTexture src, RenderTexture dst)
    {
        // 不带材质时就是拷过去
        Graphics.Blit(src, dst, effectMaterial);
    }
}

URP 里这个方法是空的

OnRenderImage 是内置管线的专属回调。在 URP / HDRP 项目里它不会报错，也不会执行——表现就是「代码明明写了，画面一点变化都没有」。新手排查后处理失效时，先确认项目用的是哪个管线。

路线三：URP Renderer Feature

URP 把渲染切成了一个个 Pass，你需要注册自己的 Pass 进流程。整体形状固定为三步：

  1. 写一个 ScriptableRenderPass，在 Execute() 里做 Blit
  2. 写一个 ScriptableRendererFeature，在 AddRenderPasses() 里把 Pass 塞进去
  3. 在 URP Renderer 资产上点 Add Renderer Feature，挂上你的 Feature
C# · URP 17 骨架 结构是稳定的，具体 API 名各版本略有差异 
using UnityEngine;
using UnityEngine.Rendering;
using UnityEngine.Rendering.Universal;

public class MyPostFeature : ScriptableRendererFeature
{
    public Material material;
    MyPass pass;

    public override void Create()
    {
        pass = new MyPass(material)
        {
            renderPassEvent = RenderPassEvent.AfterRenderingPostProcessing
        };
    }

    public override void AddRenderPasses(ScriptableRenderer renderer, ref RenderingData data)
    {
        if (material == null) return;
        renderer.EnqueuePass(pass);       // 把 Pass 排进本帧流程
    }

    class MyPass : ScriptableRenderPass
    {
        readonly Material mat;
        public MyPass(Material m) { mat = m; }

        // URP 17：从 RTHandle 取当前的相机颜色目标
        public override void Execute(ScriptableRenderContext context, ref RenderingData data)
        {
            var cmd = CommandBufferPool.Get("MyPost");
            var src = data.cameraData.renderer.cameraColorTargetHandle;

            // 申请一张临时纹理（URP 会帮你回收）
            var desc = data.cameraTargetDescriptor;
            cmd.GetTemporaryRT(Shader.PropertyToID("_MyTemp"), desc);

            // 画面 → 临时纹理（应用材质做处理）→ 回到相机目标
            Blitter.BlitCameraTexture(cmd, src, _MyTempHandle, mat, 0);

            context.ExecuteCommandBuffer(cmd);
            CommandBufferPool.Release(cmd);
        }
    }
}

这段是骨架，不是能直接跑的文件

URP 的 RTHandle 分配、Blitter 的重载签名在不同版本（12 / 14 / 17）之间改过好几次。这里的价值在于流程顺序：取源 → 申请临时 RT → 用材质 Blit → 写回 → 释放命令缓冲。真正写的时候，照着你项目版本里的官方示例补细节即可。

路线四：只想写 Shader Graph？

Full Screen Pass + Shader Graph（URP 14+）

  1. URP Renderer 资产 → Add Renderer Feature → Full Screen Pass Renderer Feature
  2. 新建一个 Fullscreen Shader Graph（不是普通的 Unlit）
  3. 用 Screen Position / Scene Color 节点采样画面，算完接到 Fullscreen Master Stack 的 Color
  4. 把 Graph 拖到 Feature 的 Pass Material 上，选择注入点（Before/After Post Processing）

这条路完全不需要写 C#，也不碰 RenderTexture，是现在做全屏特效最省事的方式。

一个能跑的后处理 Shader

HLSL · 内置管线 灰度效果：后处理 Shader 的标准模板 
Shader "Hidden/MyGrayscale"
{
    Properties
    {
        _MainTex ("Source", 2D) = "white" {}
        _Amount  ("Amount", Range(0,1)) = 1
    }
    SubShader
    {
        // 后处理的固定套路：不剔除、不写深度、永远通过深度测试
        Cull Off
        ZWrite Off
        ZTest Always

        Pass
        {
            CGPROGRAM
            #pragma vertex vert_img          // Unity 自带的全屏方块顶点函数
            #pragma fragment frag
            #include "UnityCG.cginc"

            sampler2D _MainTex;
            float4 _MainTex_TexelSize;       // (1/宽, 1/高, 宽, 高)，做模糊要用
            float _Amount;

            fixed4 frag (v2f_img i) : SV_Target
            {
                fixed4 c = tex2D(_MainTex, i.uv);

                // 感知亮度权重，比简单的 (r+g+b)/3 更符合人眼
                float gray = dot(c.rgb, float3(0.299, 0.587, 0.114));

                return fixed4(lerp(c.rgb, gray.xxx, _Amount), 1.0);
            }
            ENDCG
        }
    }
}

想改成边缘检测，只需要把「取当前像素」改成「取周围一圈像素」：用 _MainTex_TexelSize.xy 当步长，采样上下左右四个邻居，算它们和中心像素的差值，差值大的地方就是边缘。这就是 Sobel 算子，也是描边的雏形。

URP 里想「读到场景颜色」有更省事的办法

  • _CameraOpaqueTexture：URP 自动生成的不透明场景截图，直接采样即可（要开 Opaque Texture）。
  • _CameraDepthTexture：深度图，做景深、雾、轮廓光、水面都用它。
  • Shader Graph 里对应 Scene Color 和 Scene Depth 节点。

五个坑

症状原因修法
运行几秒后显存爆掉 RenderTexture 没 Release()，每帧 new 一张 在 OnDestroy / OnDisable 里释放；或复用同一张
换分辨率后画面被拉伸 / 模糊 RT 尺寸还是旧的 监听分辨率变化，rt.Release() 后重建
后处理代码写了但毫无效果 URP 项目里用了 OnRenderImage 改用 Renderer Feature / Full Screen Pass
颜色发灰、发白，和编辑器里不一样 RT 的 sRGB 设置不对（Linear 空间项目里尤其明显） 用 RenderTextureFormat.Default，别手动指定 sRGB 标志
后处理之后 UI 也变灰了 / UI 没变灰 后处理作用在哪个相机上 把 UI 相机和主相机分开，只在主相机上挂后处理

自测：三题

自测 · 3 个问题（先自己答，再展开）
  1. 为什么后处理 Shader 要写 ZTest Always 和 Cull Off？ 因为那个全屏方块是硬塞在相机前面的，它不应该被深度测试挡住，也不该有背面剔除的问题。后处理的原则是：无条件盖住整个屏幕。
  2. 为什么模糊要拆成横向和纵向两趟？ 采样数从 N² 降到 2N。3×3 是 9 次变 6 次，看起来差别不大；但 15×15 是 225 次变 30 次，性能差 7 倍以上。两趟的结果在数学上非常接近真正的二维高斯。
  3. 一个后处理同时作用于场景和 UI，会有什么问题？ UI 通常需要保持清晰锐利（文字模糊会很难看），而且 UI 往往在单独的 Canvas / 相机上。正确做法是把后处理限制在 3D 相机上，UI 相机叠加在上层。

读完之后

五章到这里就闭环了：坐标系统决定了「你在哪个空间算」，摄像机决定了「什么被看到」，光照决定了「表面多亮」，法线贴图决定了「细节多细」，帧缓冲决定了「画完之后还能做什么」。

接下来最有效的练习，不是继续读，而是挑一个你喜欢的游戏画面，试着用这五章的语言描述它是怎么来的：这个高光是 Blinn 还是 PBR？这个描边是后处理还是法线外扩？这个水面是反射贴图还是屏幕空间？能描述清楚，你就已经具备「看懂」的能力了。

如果还要继续深入

  • PBR：把 Blinn-Phong 换成「微表面 + 能量守恒」，Unity 的 URP Lit 就是这个。看原教程的 PBR 章节，但重点看图。
  • 阴影：Shadow Map 就是「从光源的视角渲染一张深度图」，本质还是本章的帧缓冲。
  • 后处理进阶：Bloom（多级降采样 + 模糊 + 叠加）、SSAO、景深，都是本章套路的组合。
