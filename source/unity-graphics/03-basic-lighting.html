第 03 章 · 基础光照

光照的全部秘密，藏在一个点乘里

如果表面正对光源，它最亮；侧过来，就变暗；背过去，全黑。这三个状态可以用一个点乘精确描述。整章 Blinn-Phong 模型就是这句话的数学化：环境光负责「不死黑」，漫反射负责「有立体感」，高光负责「有材质感」。

一句话

一个像素的颜色 ≈ 环境光（哪儿都有的底光）+ 漫反射（max(N·L, 0) × 光色 × 物体色）+ 高光（pow(max(N·H, 0), 光泽度)）。记住 N、L、V、H 四个向量，就够调所有材质的观感了。

为什么是点乘，而不是别的

点乘的几何定义是 a·b = |a||b|cosθ。两根都归一化的向量点乘，结果就是夹角的余弦：

  • 夹角 0°（正对）→ cos 0 = 1 → 最亮
  • 夹角 60° → cos 60 = 0.5 → 一半亮度
  • 夹角 90°（侧对）→ cos 90 = 0 → 全黑
  • 夹角 > 90°（背对）→ 余弦为负 → 需要 saturate 夹到 0

而「亮度」的物理本质就是单位面积接收到多少光。光斜着照过来时，同样的光被摊在更大的面积上，单位面积自然更少——这个「摊薄」的比例，正好就是余弦。所以点乘不是凑出来的，它就是这件事本身。

三项的公式

Blinn-Phong

环境光 = 环境强度 × 光颜色 × 物体颜色 漫反射 = max(N·L, 0) × 光颜色 × 物体颜色 高光 = pow( max(N·H, 0), 光泽度 ) × 光颜色 × 高光颜色 最终颜色 = 环境光 + 漫反射 + 高光

环境光：负责「不死黑」

物理上它不存在（光总得有来源），但完全按物理算，背光面会纯黑，看起来像剪影、很假。环境光就是一个作弊项：假装整个世界都在微微发光，把所有表面提亮一点点。Unity 里它是 Camera 的 Ambient 设置（内置管线是 Skybox / Gradient / Color 三选一）。

漫反射：负责「立体感」

就是 N·L 本身。它和相机无关——你从哪个角度看，亮度都一样。这一点很关键：转相机时如果漫反射变了，说明你算错了。

高光：负责「材质感」

pow(N·H, 光泽度) 里的指数越大，高光斑越小越锐利：

光泽度指数观感Unity 里对应
4 ~ 8大面积柔光，像橡胶、粉笔Smoothness ≈ 0.1
32 左右明显的圆形高光，像塑料Smoothness ≈ 0.5
128 以上小而亮的高光点，像金属、玻璃Smoothness ≈ 0.9

Blinn 和 Phong 的差别，就一个向量

原始的 Phong 模型算的是反射向量和视线的夹角：pow(max(R·V, 0), gloss)。Blinn 把它换成了半程向量和法线的夹角：pow(max(N·H, 0), gloss)。

Phong：算 R·V

需要先算出反射向量 R = reflect(-L, N)，再做点乘。物理上更「正」，但反射在掠射角容易估错，高光边缘会发脏。

Blinn：算 N·H

只需要一次加法 + 一次归一化，就得到 H。更快，而且在掠射角下高光形状更自然。几乎所有引擎（包括 Unity）默认用这个。

代价是：Blinn 的高光在极端角度下会比 Phong 稍大一点。为了对齐观感，通常要把 Blinn 的指数乘个 4 左右（gloss_blinn ≈ 4 × gloss_phong），这也正是 Unity 里 Smoothness → exponent 映射时隐式做的事。

性能直觉

平行光无论多少个物体都只算一次方向，最便宜。点光和聚光要按每个物体的距离逐个计算，而且是前向渲染下每个片元都要乘一遍。手机上「多打几盏点光就掉帧」，原因就在这里。URP 里可以让额外的灯走 Additional Lights 并用 Forward+ / Deferred 缓解。

HLSL · 内置管线 自己写一遍 Blinn-Phong 
// 都在世界空间里算，避免空间混用
float3 N = normalize(UnityObjectToWorldNormal(v.normal));   // 法线 → 世界
float3 V = normalize(UnityWorldSpaceViewDir(i.worldPos));   // 指向相机

// _WorldSpaceLightPos0：平行光时 xyz 就是「光的方向」
float3 L = normalize(_WorldSpaceLightPos0.xyz);

float3 H = normalize(L + V);                         // 半程向量
float  NdotL = saturate(dot(N, L));                  // 记得 saturate！
float  NdotH = saturate(dot(N, H));

float3 albedo   = tex2D(_MainTex, i.uv).rgb;
float3 lightCol = _LightColor0.rgb;

float3 ambient  = UNITY_LIGHTMODEL_AMBIENT.rgb * albedo;
float3 diffuse  = NdotL * lightCol * albedo;
float3 specular = pow(NdotH, _Gloss) * lightCol * _SpecColor.rgb;

float3 color = ambient + diffuse + specular;
return fixed4(color, 1.0);
HLSL · URP 17 URP 里同样的事，用 Light 结构体 
#include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Lighting.hlsl"

Light mainLight = GetMainLight();            // 拿场景里最重要的那盏方向光
float3 N = normalize(i.normalWS);
float3 V = normalize(i.viewDirWS);

float  NdotL = saturate(dot(N, mainLight.direction));
float3 H     = normalize(mainLight.direction + V);
float  NdotH = saturate(dot(N, H));

float3 diffuse  = NdotL * mainLight.color * _BaseColor.rgb;
float3 specular = pow(NdotH, _Smoothness * 100.0) * mainLight.color;

float3 color = diffuse + specular + SampleSH(N);   // SampleSH 提供环境光

Shader Graph 里怎么连

  1. Normal Vector 节点，Space 选 World。
  2. Dot Product：A = 法线，B = 光方向（用 Light Direction 节点，或自己填一个 Vector3）。
  3. 接 Saturate，再 Multiply 两次：乘 Base Color、乘光颜色。
  4. 高光：Normalize(L + V) → 再和法线 Dot Product → Power（指数 = Smoothness × 100）。
  5. 三项 Add 到一起，接到 Base Color 或 Emission。

这五步和上面的 HLSL 是同一件事的两种写法。看懂一种，另一种自然通。

六个坑

症状原因修法
背光面出现奇怪的花纹 / 反而变亮 没做 saturate，负值参与了颜色计算 所有点乘结果都夹到 0..1
物体转向时亮度忽明忽暗，甚至闪烁 法线在模型空间，光方向在世界空间 统一到世界空间：UnityObjectToWorldNormal()
缩放变形后光照全黑 / 一块一块 非均匀缩放，法线没走「逆转置」 用 UnityObjectToWorldNormal()，并对插值后的法线 normalize
开了阴影，但自己写的光照没有阴影 阴影是额外的一趟 Shadow Map，需要宏和采样 内置管线加 SHADOW_COORDS / SHADOW_ATTENUATION；URP 用 GetMainLight(shadowCoord)
高光是一整片糊的，没有亮点 指数太小（比如写死 8） 指数跟 Smoothness 绑定，金属/玻璃给到 128 以上
低模上光照「一块一块」的色阶 在顶点着色器里算光照（Gouraud） 移到片元着色器（Per-Pixel）

自测：三题

自测 · 3 个问题（先自己答，再展开）
  1. 转动相机，镜面高光会跟着移动吗？漫反射会吗？ 高光会（因为 H 依赖 V），漫反射不会（只看 N 和 L）。这正是区分两者的最快办法：如果一个「高光」不随视角变化，它其实是被画进贴图的假高光。
  2. 为什么高光要用 pow，而漫反射不用？ 漫反射的能量分布在很大角度范围内，余弦本身就够；高光集中在很小的角度内，需要一条「陡峭」的曲线把 0.9 和 0.99 拉开差距，幂函数就是这个陡峭化工具。
  3. _WorldSpaceLightPos0 对点光和对平行光的含义一样吗？ 不一样。平行光时它是方向（w = 0），点光时它是位置（w = 1）。所以点光要自己算 normalize(lightPos - worldPos)——少了这一步，点光会像平行光一样「没有远近」。
